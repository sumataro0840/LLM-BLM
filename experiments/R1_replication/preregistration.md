利用者の依頼（2026-10-25）：S1〜S4 の結果が、別の会社でも出るか再現する。

## 1. 位置づけ

- S1〜S4 は同じ 1,000 社（元の標本）で行い、S2〜S4 は S1 の結果を見た後に設計した。BLM の推移が比べる相手を上回ったことは、検定していない（S1 の追記 1 で「報告だけ」と決めた）。
- 問い：(1) S1〜S4 の主な検定の結果は、別の 1,000 社でも同じになるか。(2) S4 の形の BLM（ChronoGPT の見通し・株価で補正した共分散・TE の校正）は、比べる相手を上回るか。

## 2. 新しい標本

- `smallcap/replica.py`：元の標本を選んだのと同じ条件（小型株の範囲に一度でも入った会社のうち、いま上場して株価があり、2016 年以降の決算の 8-K が 4 件以上）を満たす 2,400 社から、元の 1,000 社を除いた 1,400 社のうち、1,000 社を乱数の種 1 で選んだ（重なり 0）。
- データベースは `data/smallcap_rep.sqlite`（元のデータベースのコピーから、決算発表文と点数の表を空にしたもの）。決算発表文・財務データ・驚き・点数（辞書、FinBERT、ChronoGPT、gpt-4o-mini）は、元の標本と同じコードで作る。
- 実行：S1〜S4 の `run.py`（と S1 の `blm_paths.py`）を、環境変数 `SMALLCAP_DB=data/smallcap_rep.sqlite`、`SMALLCAP_CACHE=data/cache/smallcap_rep`、`SMALLCAP_RESULTS=results_rep` で、元と同じ順に 1 回ずつ実行する。設定（期間、窓、統制、判定の基準、乱数の種）は、すべて元の事前登録と同じ。

## 4. 新しい主な検定：BLM は比べる相手を上回るか（R-BLM）

- 対象：新しい標本で、2015 年末から、四半期ごと、ChronoGPT＋リッジの見通し、共分散 B（株価で補正）、TE の校正あり（S4 の `B_cal`）の BLM。
- 評価する日：2017-01-01 以降（S4 と同じ）。
- 日次の超過リターン a_t = ポートフォリオ − 比べる相手（範囲を浮動株時価総額で加重）。S4 の `results_rep/u.csv` の u_t × (3% / √252)。
- **P**：a_t の平均 > 0 か。
- 判定：円形のブロック・ブートストラップ（ブロック 63 日、2,000 回、乱数の種 0）で平均の分布を作り、平均* ≤ 0 の割合を片側 p とし、p < 0.05 なら「支持」。
- 報告：年率の超過リターン（平均 × 252）、実現の TE、情報レシオ、ブートストラップの 95% 区間。
- 費用は S4 と同じ（片道 0.3%、両方から）。
