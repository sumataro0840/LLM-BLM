比率の計算と、元の S&P500 との比較

LLM の予想から Black-Litterman と最適化で比率を計算し、5つの戦略を30か月分比べた最初の結果です。計算は通りましたが、比率が少数の銘柄に集中するという問題が見つかりました。

関連資料計画は LLM-BLM_今後の計画.html、評価の観点は LLM-BLM_評価ポイント.html、テーブルの定義は LLM-BLM_DB設計.html にあります。

計算は最後まで通りました。ただし、今の設定では Black-Litterman の比率が1〜2銘柄に集中し、「S&P500 の比率を調整した」と言える形になっていません。成績を論じる前に、予想の大きさの扱いを決める必要があります。

5なぜ集中するか

成績を見ずに、比率の形だけで原因を調べました。

比べるもの大きさ
市場の均衡が示すリターン（全銘柄の平均）1日 +0.01〜0.03%
LLM の予想（全銘柄の平均）1日 -0.17〜+0.28%（月による）。均衡の約10倍
LLM の回答の分散 ÷（τ × 銘柄の分散）中央値で 0.10〜0.29。予想の方が、均衡より数倍信頼されている
LLM の回答の分散 ÷ 実際の予測誤差の目安中央値で 0.05〜0.15。LLM は、実際の10〜20倍の自信を持っていることになる

30個の回答のばらつきは「同じ質問への答えのぶれ」で、「予想がどれだけ当たるか」ではありません。最初の確認では、予想と実際の順位相関は +0.05 でした。ほとんど当たらない予想を、強く信じる設定になっています。

6元の設定との比較

元の実装の計算を、同じ銘柄・同じ予想で再現しました。成績は良く見えますが、調べると3つの不備があり、その組み合わせで結果が決まっています。

点確認したこと結果への影響
均衡リターンの単位日次のリターンから年率の金利（0.02）を引いているため、均衡リターンが1日 -0.7〜-1.7% という、あり得ない値になる小さい。予想が強く信じられる設定なので、修正後の期待リターンは予想とほぼ同じになる（均衡が何であっても結果が変わらない）
共分散のデータ不足約480銘柄に対して20日分。行列の実質的な次元は 18〜20 しかない中くらい。統計的には問題だが、この計算ではリターンの項が支配的で、比率への影響は限られる。計算上のリスク（年率19%）は、実績（年率24%）より小さく出る。詳しくは 元論文の計算の問題点
最適化が途中で止まる3つの月で、元の最適化の結果と、同じ目的関数の正しい最適解を比べた。元の結果は最適解に届いておらず、実質的な銘柄数は 6.7〜8.3（正しい解は 3.6〜4.5）大きい。「分散された比率」は、最適化が途中で止まったことによる偶然の産物
読み取れること：元の設定の結果は、「LLM の予想 + Black-Litterman」の効果というより、「予想の高い銘柄を、途中で止まった最適化で数銘柄〜十数銘柄選んだ」結果です。直した設定で1〜2銘柄に集中するのは、計算を正しくしたことで、予想の大きさの問題がそのまま表に出たためです。

7次に決めること

「S&P500 の比率を、LLM の予想で少し調整する」形にするには、予想の大きさか、指数からのずれのどちらかを抑える必要があります。

案内容良い点注意
A. 指数からのずれに上限を付ける最適化に「元の S&P500 とのずれ（年率）を X% 以内」という条件を足す。X は .env で指定目的（比率の調整）にそのまま合う。実務でも普通のやり方。X の意味が分かりやすいX をどう決めるかは、成績を見ずに決める（たとえば 2%）
B. 予想を「当たり具合」に合わせて縮める予想の不確かさ（Ω）を、回答のばらつきではなく、予想が実際にどれだけ当たるかから決めるBlack-Litterman の考え方として筋が通る。「LLM の自信は当てにならない」という発見を、そのまま設計に反映できる当たり具合を測るデータが要る。評価期間で測ると先読みになるので、前半で測って後半で使う
C. 1銘柄の比率に上限を付けるたとえば「時価総額の比率の ±1% まで」単純根拠が弱い。上限に張り付いた比率になりやすい

おすすめは A です。条件を1つ足すだけで、どの戦略にも同じ形で使えます。B は、その後の発展として、前半で測った当たり具合を後半に使う形で試せます。

この結果自体は、評価ポイントの「批判的に読めているか」の材料になります。「元の結果は、最適化が途中で止まったことに依存していた」「LLM の回答のばらつきは、予想の信頼度として使えない」の2点は、数字で示せます。

9再計算の方法

cd LLM-BLM
python run_blm.py        # .env の BLM_* の設定で、比率を計算して保存する（約6分）
見たいもの場所
計算の条件テーブル portfolio_runs（今回の5つは portfolio_id 1〜5）
比率テーブル portfolio_weights
翌月のリターンビュー portfolio_returns
計算のコードblm/（共分散、均衡リターン、Black-Litterman、最適化、戦略）
-- 戦略ごとの月次リターン
SELECT r.strategy, p.as_of_date, p.end_date, p.n_holdings, p.period_return
FROM portfolio_returns p JOIN portfolio_runs r USING (portfolio_id)
ORDER BY p.as_of_date, r.portfolio_id;
