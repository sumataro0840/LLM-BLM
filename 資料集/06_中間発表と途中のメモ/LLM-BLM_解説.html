LLM-BLM リポジトリ解説

LLM の「見通し」を Black-Litterman モデルに入れてポートフォリオを組む

論文 Integrating LLM-Generated Views into Mean-Variance Optimization Using the Black-Litterman Model（arXiv 2504.14345、ICLR 2025 Workshop）の公式実装について、コードの構成と処理の流れをまとめたページです。

1概要

STEP A

LLMに予想させる

各銘柄の「先月の日次リターン」と「会社情報」を渡し、来月の平均日次リターンを1つの数値で答えさせます。

STEP B

30回聞いて自信を測る

同じ質問を30回繰り返します。回答の平均を見通し（ビュー）、分散を自信のなさとして扱います。

STEP C

BLMで混ぜて最適化

市場均衡リターンとLLMのビューをBlack-Littermanモデルで合成し、平均分散最適化で配分を決めます。

対象：S&P500 約500銘柄（共通497銘柄） LLM：Llama-3.1-8B / Gemma-7B / Qwen2-7B 期間：2024年6月〜12月 比較対象：S&P500指数・等ウェイト・MVO

5各ステップの詳細

1

データ取得とLLMビューの収集 run.py

入力：Wikipedia / yfinance / LLM API出力：yfinance/*.csv, responses/*.json
  1. Wikipediaから S&P500 の銘柄一覧（Symbol・社名・GICSセクター・サブ業種）を取得します。
  2. 2024-06〜12 の各月について、yfinanceで終値を取得し data_*.csv に、pct_change() で求めた日次リターンを returns_*.csv に保存します。
  3. 銘柄ごとに、会社情報と先月の日次リターン列をプロンプトに入れてLLMに質問します。
  4. 1銘柄につき30回呼び出します。guided_json で出力を {"expected_return": float} の形に固定しています。
  5. Gemmaはシステムプロンプトに対応していないので、ユーザープロンプトの先頭に連結します。パースに失敗した回はスキップします。

保存されるJSONの例（1銘柄分）

"A": {
  "ticker": "A",
  "Security": "Agilent Technologies",
  "GICS Sector": "Health Care",
  "GICS Sub-Industry": "Life Sciences Tools & Services",
  "pct_change":      [ -0.0109, 0.0028, ... ],   // 先月の日次リターン（約20日分）
  "expected_return": [ -0.0005, 0.0088, ... ]    // LLMの予想 30個
}
2

共通銘柄の抽出 responses/get_common_stocks.py

入力：responses/*.json出力：common_stocks.json

すべてのJSONファイルに共通して出てくる銘柄を抽出します。月による銘柄の入れ替えやデータ欠損の影響を除くための処理です。

os.listdir('.') を使っているため、responses/ に移動してから実行する必要があります。
3

比較用ポートフォリオ baselines.py

入力：returns_*.csv, market_caps.json, common_stocks.json出力：responses_portfolios/*_{月}.csv

前処理として、時価総額データと共通銘柄で銘柄を絞り込み、NaNのある列を除きます。J と TSCO は明示的に除外しています。

戦略ウェイトの決め方
EW（等ウェイト）全銘柄に 1/N ずつ配分
MVO（平均分散最適化）wᵀΣw − 0.1·μᵀw を最小化します。μ と Σ はt月の標本平均と標本共分散です。制約は「ウェイトの合計が1」と「0 ≤ w ≤ 1（空売りなし）」で、SLSQPで解きます。
4

月別結果の連結 responses_portfolios/combine_portfolio.py

入力：*_portfolio_{月}.csv出力：equal_weighted_portfolio.csv / optimized_portfolio.csv

月別のCSVをファイル名順に縦に連結し、全期間の日次リターンを1本のファイルにします。

5

Black-Litterman でウェイトを計算 evaluate_multiple.py

入力：returns_*.csv, responses/*.json, market_caps.json出力：results/*_weights_tau_0.025.csv

このリポジトリの中心です。process_period() が月ごとに次の処理をします（計算の中身は6章）。

  1. 時価総額の比率で重み付けした市場リターンとベータから、市場均衡リターン Π を作る
  2. LLMの30個の予想から Q（平均） と Ω（分散） を作る
  3. Black-Litterman の式で事後リターン μBL を求める
  4. MVOと同じ目的関数と制約で最適化し、ウェイトを求める
現状のコードでは Gemma だけが有効で、Llama と Qwen の行はコメントアウトされています。
6

LLMポートフォリオのリターン計算 calculate_llm_returns.py

入力：results/*_weights_*.csv, returns_*.csv出力：results/*_returns_tau_0.025.csv

6〜11月のウェイトを、それぞれ翌月の日次リターンに掛けてポートフォリオの日次リターンを求めます。3モデル分を連結して保存します。

7

評価と可視化 portfolio_weight_plot.ipynb

入力：上記の全リターンCSV出力：統計表、累積リターンの図
  • S&P500指数（^GSPC）の日次リターンを作ります。
  • 次の6戦略を比較します：S&P500 / EW / MVO / BLM-Llama / BLM-Gemma / BLM-Qwen
  • 指標：年率換算の累積リターン、年率平均、年率標準偏差、Sharpe比（無リスク金利2%）、MDD
  • 累積リターンのグラフ、LLMビューの平均・分散の分析、時価総額順のウェイト比較を作ります（figure/ の図に対応）。

6Black-Litterman の中身

(a) 事前分布：市場均衡リターン Π

R_m = Σ (時価総額ウェイト_i × R_i) … 時価総額で重み付けした市場リターン
β_i = Cov(R_i, R_m) / Var(R_m) … 各銘柄のベータ
Π = β × mean(R_m − 0.02) … 市場均衡リターン

(b) LLMのビュー

記号中身意味
Q30個の予想の平均（銘柄ごと）LLMが考える来月のリターン
P単位行列「銘柄iのリターンはQi」という絶対ビューを全銘柄に置く
Ω対角成分が30個の予想の分散回答がばらつく銘柄ほど、ビューを弱く扱う
Σt月の標本共分散行列銘柄間のリスク構造
τ0.025事前分布の不確実性の大きさ（ハイパーパラメータ）

(c) 事後リターン

M = [ (τΣ)⁻¹ + Pᵀ Ω⁻¹ P ]⁻¹
μ_BL = M · [ (τΣ)⁻¹ Π + Pᵀ Ω⁻¹ Q ]
逆行列には、特異行列でも計算できる np.linalg.pinv を使用

(d) 最適化

minimize wᵀΣw − 0.1 · wᵀμ_BL
subject to Σw = 1, 0 ≤ w ≤ 1
直感的には：LLMの回答が毎回ほぼ同じ（分散が小さい）銘柄では、そのビューが事後リターンに強く反映されます。回答がばらつく銘柄では市場均衡 Π に近い値になります。

7実行手順

# ① LLMの予想を集める（モデルごとに実行）
python run.py --model_name llama
python run.py --model_name gemma
python run.py --model_name qwen

# ② 共通銘柄を抽出（responses/ に移動して実行）
cd responses && python get_common_stocks.py && cd ..

# ③④ ベースライン
python baselines.py
python responses_portfolios/combine_portfolio.py

# ⑤⑥ LLM + Black-Litterman（必ずこの順）
python evaluate_multiple.py
python calculate_llm_returns.py

# ⑦ portfolio_weight_plot.ipynb を実行
READMEでは calculate_llm_returns.py が先に書かれていますが、実際には ⑤ → ⑥ の順でないと動きません。⑥は⑤が出力するウェイトCSVを読み込むためです。
