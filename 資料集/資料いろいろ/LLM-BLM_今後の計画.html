LLM-BLM 今後の計画

これからやりたいことと、その進め方

LLM の予想を使った比率の調整、結果へのフィードバック、セクター単位の予想という3つの段階について、論点の置き方、情報の漏れのふさぎ方、今後足す入力、必要なテーブル、進める順番をまとめます。

関連資料今あるテーブルとビューは LLM-BLM_DB設計.html、データの作り方と注意点は LLM-BLM_データの扱い方.html にあります。この資料は、これから作るものの計画です。

1要点

今の目的：細かい改善より先に、最後まで一度通すこと。LLM の予想から、比率の調整、元の S&P500 との比較までを動かします。
レポートの主役：モデルの比較ではなく、設計にします。見せ場は、未来の情報が漏れる経路を1つずつふさいだことです。
3 段階
比率の調整 → フィードバック → セクターの予想
あと 5 テーブル
段階1で2つ、段階2で2つ、段階3で1つ（今は9つ）
月次がメイン
評価できる回数が30回ある。四半期は10回
共分散は直近1年
日次リターンで計算し、毎月更新する。補正が必要

表の「案」は、まだ決めていない提案です。名前や列は、作るときに変わる可能性があります。

2論点の置き方

主役：設計

当時知り得た情報だけで動く仕組みを作り、LLM の予想を Black-Litterman に入れた比率を、元の S&P500 と比べる。

脇役：モデルの比較

余裕があれば足す確認にとどめる。元の論文がすでにやっていて、予算・期間・知識の期限の問題で、はっきりした結論を出しにくい。

使うモデル

  • gpt-4o-mini を使い続けます。知識が2023年10月までなので、評価期間（2024年4月〜2026年9月）の30か月すべてを「答えを知らない状態」で評価できます。料金も、個別銘柄の30か月分で4〜5ドルです。
  • この利点は、渡す情報が当時のものだけである場合に限ります。入力から未来が漏れると、モデルが知らなくても意味がなくなります（「情報が漏れる経路」の章）。
  • モデルを比べる場合は、セクターの予想（段階3）で行います。1か月に聞くのは11セクターだけなので、上位モデルでも数ドル〜数十ドルで済み、評価の回数（30回）も減りません。成績は、モデルの知識の期限の前と後で分けて出します。
  • 予算の上限は、全部合わせて5万円（300ドル強）です。

3全体の流れ

済み

データと LLM の予想

株価・構成銘柄・比率・財務諸表を DB に保存。LLM に各銘柄の翌月リターンを30個ずつ答えさせて保存（2024年4月〜2026年9月の予想。2026-10-10 に実行）。

段階1・次にやる

比率の調整

LLM の予想を Black-Litterman に入れ、最適化（QP）で比率を決める。元の S&P500 の比率と、翌月のリターンを比べる。

段階2

フィードバック

なぜ良かったか・悪かったかを、運用会社の月次レポートを参照して LLM に説明させる。月に1回の会話。

段階3

セクターの予想

レポートと過去の値動き・財務データから、セクター単位で予想させる。セクター内の比率は、ベータと時価総額で調整する。

4段階1：比率の調整まで

LLM の予想（llm_view_stats の平均と分散）から、調整後の比率を計算して保存します。

市場の均衡リターンを出す

判断日の時価総額の比率（index_weights）と共分散から逆算する。保存しない。

LLM の予想と混ぜる（Black-Litterman）

30個の回答の平均を「予想」、分散を「予想の不確かさ」として、均衡リターンを修正する。

最適化（QP）で比率を決める

修正後の期待リターンと共分散から、空売りなし・合計1の条件で比率を求める。

翌月のリターンを比べる

調整後の比率と、元の S&P500 の比率（時価総額加重）で、それぞれ翌月のリターンを計算する。

7設計の見せ場：情報が漏れる経路をふさぐ

過去のデータで戦略を試すとき、判断した時点では知り得なかった情報が混ざると、成績が実力より良く見えます。この研究では、漏れる経路を1つずつ挙げて、ふさいだかどうかを示します。

経路どう漏れるかふさぎ方状態
① モデルの知識LLM が、評価期間の相場を学習で知っている知識の期限が評価期間より前のモデルを使う（gpt-4o-mini は2023年10月まで、評価は2024年4月から）。プロンプトに日付を入れない済み
② 渡す資料レポートや要約に、後から書かれた内容が混ざる公表日が判断日以前の資料だけを使う。AI に検索させず、渡した資料だけを整理させる。引用元の日付を確認する段階2・3
③ 構成銘柄後から指数に入った銘柄を、過去にさかのぼって使う判断日に在籍していた銘柄だけを対象にする（index_membership）済み
④ 財務データの提出日まだ公表されていない決算や、後から修正された数字を使う提出日（filed_date）が判断日以前の値だけを使う。保存しているのは最初に提出された値データは済み 判断日で絞るビューは段階3
⑤ 株価と共分散判断日より後の株価を、入力や共分散に使う入力は判断日までのリターン。共分散も判断日までの1年分入力は済み 共分散は段階1
⑥ 設定やモデルの選び方評価期間の成績を見て、設定（τ など）やモデルを選ぶ選ぶ期間と、成績を示す期間を分ける段階1で区切りを決める

ふさぎきれていない経路（レポートに書く）

経路内容影響
除外した28銘柄「後で上場廃止になった」という当時は分からない情報で、対象から外している。無料のデータでは株価が取れない生存者バイアス。全戦略に同じ除外を適用するので、戦略同士の比較は公平
社名・ティッカー・セクター当時のものではなく、2026年10月時点のものを LLM に渡している小さい。後の社名変更などが伝わる
要約に使う AI の知識資料の要約を新しいモデルにさせると、要約に未来の知識が混ざる可能性がある何か月分かを元の資料と読み比べて確認する

漏れの影響を測る実験

同じ月について、A：検索して書かせたレポート（未来の情報が混ざる）と、B：当時の資料だけから作ったレポートを用意し、それぞれを入力にした場合の成績を比べます。A だけ成績が良ければ、漏れの影響を数字で示せます。2025-01_sector_report.md は A の実例として使えます。

変数ごとの検討メモ

政策金利：入れる。水準より変化

会合は年8回で、水準は変わらない月の方が多いです。効くのは「3か月前からの変化」と「長期と短期の金利差」で、金融・不動産・公益の判断材料になります。gpt-4o-mini は評価期間の金利を知らないので、渡さないと古い前提（5.25〜5.5%）で考えます。3か月物の国債利回りが、政策金利の代わりになります。

下落リスクの出し方：実績から直接求める

共分散から計算した VaR は、標準偏差を定数倍しただけなので、変動の大きさを渡すのと同じ情報です。下落の情報を渡すなら、過去1年の実際の日次リターンから、下位5%の日の平均（CVaR）や最大下落率を求めます。リスクは最適化の側ですでに共分散として使うので、LLM に渡すのは2〜3個で十分です。

オプションの情報：VIX で足りる

VIX は S&P500 のオプションから計算された指数なので、オプションの情報の要約です。自分で分布を推定する必要はありません。足すなら、期間別の差（3か月 − 1か月。マイナスは目先の強い警戒）と、歪度の指数です。尖度の指数はありません。VIX は実際の変動より高めに出るので、水準そのものより、時期ごとの高い・低いで使います。

先物：期待リターンは取れない

株価指数の先物価格は「現物 + 持ち越しのコスト」で、相場の見通しは入っていません。オプションから出る分布も、中心は無リスク金利に固定されます。期待リターンは、時価総額の比率から逆算する均衡リターン（Black-Litterman の出発点）から取ります。金利の先物からは、政策金利の見通しが取れます。

全体の考え方：市場価格に入っている情報は市場から取り、LLM にはそこからのずれだけを答えさせます。期待リターンは均衡リターン、変動の大きさは VIX、銘柄どうしの連動は過去1年の株価、金利の見通しは国債利回りから取ります。どれも判断日の価格そのものなので、漏れの心配がありません。

データの確認：VIX（9日・1か月・3か月・6か月）、歪度の指数、債券の予想変動率、国債利回り（3か月・5年・10年・30年）、先物（S&P500、10年債、政策金利の直近の限月）は、yfinance で2023年3月〜2026年9月の全期間が取れることを確認済みです。^GSPC と同じように tickers と prices に入れられるので、テーブルは増えません。

どの変数を使うかの決め方

候補を全部入れると、何が効いたのか分からなくなります。統計モデルで変数を選び、選んだ後は変えません。

評価期間より前のデータを用意する

値動き・金利・VIX は何十年分も取れる。セクターの値動きは、セクター別の ETF（1998年から。不動産は2015年、通信サービスは2018年から）で代用する。たとえば2010〜2023年を使う。

統計モデルで変数を選ぶ

「そのセクターが翌月、指数全体を上回ったか」を予測する。効かない変数の係数が自動的に0になる方法（L1 正則化）を使い、残った変数を採用する。

変数を固定して、評価期間で使う

2024年以降の結果を見て変数を入れ替えない。入れ替えると、「漏れる経路」の⑥（設定の選び方）に当たる。

限界：統計モデルで効く変数と、LLM で効く変数は同じとは限りません。文章（④）は、この方法では選べません。あくまで数字の変数を絞る目安です。

比較用の統計モデル：ロジスティック回帰を主にする

変数を選ぶのに使ったモデルは、そのまま LLM の比較相手になります。同じ変数を渡したとき、LLM が統計モデルに勝てるかを見ます。候補は、ロジスティック回帰と XGBoost（決定木を多数組み合わせる方法）です。

ロジスティック回帰XGBoost
データの量との相性少なくても安定するデータが少なく雑音が多いと、過去に合わせすぎやすい。月次・セクター単位では数千件しかない
結果の読みやすさ係数の符号と大きさで、どの変数がどちらに効くかが分かる重要度は出るが、向きや理由は読み取りにくい
統計的な検定変数ごとにカイ二乗検定ができるできない
調整する設定正則化の強さ1つ木の深さ、本数、学習率など多い。設定を選ぶこと自体が漏れの経路になる
変数の組み合わせの効果直線的な関係しか見ない「金利が上がっていて、かつ変動が大きいとき」のような組み合わせを拾える
  • 主に使うのはロジスティック回帰です。データが少ないこと、どの変数が効いたかを説明する必要があること、設定の少なさが理由です。
  • XGBoost は、確認用に1回だけ使います。「直線的でない関係を見落としていないか」を確かめるためです。評価期間より前のデータの中で、学習に使っていない期間の成績を比べます。XGBoost がはっきり上回らなければ、ロジスティック回帰だけで進めます。
  • 比較から読み取れること：数字だけを渡して LLM が回帰に勝てないなら、数字の処理は回帰で十分です。LLM の強みが出るとすれば、回帰では扱えない文章（レポート）を足したときです。「LLM は何を足しているのか」を示せます。

どの変数が効いたかの出し方

寄与は LLM に答えさせず、数字で出します。LLM は統計量を正しく計算できず、「金利を重視しました」といった自己説明も、実際の挙動と一致するとは限らないためです。

知りたいこと方法内容
どの入力が LLM の予想を良くしたか入力を抜き差しして比べるまとまりを1つずつ足した実行を別々に保存し、成績の差を見る。差がその入力の寄与。セクターの予想は1回の実行が30問なので、何通り試しても安い
どの変数が統計的に効いているか回帰の検定ロジスティック回帰で、その変数を入れた場合と抜いた場合の当てはまりの差を検定する（尤度比検定。カイ二乗検定の一種）
比率の差のうち、何が成績に効いたか要因分解セクターの配分の差と、セクター内の銘柄の差に分ける
  • フィードバックの LLM の役割は、説明です。上の数字の表と当時のレポートを受け取り、「この月は金利の入力が効いた。レポートによれば、利下げ観測で不動産が買われたため」のように文章にまとめます。計算はさせません。
  • どの入力を使った実行かは、llm_runs に列を足して記録します。テーブルは増えません。
  • 30か月では、差がはっきり出ない可能性が高いです。「効いた・効かなかった」と言い切らず、差の大きさと、そのぶれの幅を一緒に示します。

入力を足すときの決まり

  • どの入力にも「いつ知り得たか」の日付を持たせます。日付が分からない情報は使いません。
  • まとまりごとに足して、効果を切り分けます。①値動き → ②財務 → ③市場環境 → ④文章の順に足し、それぞれ別の実行（run_id）として保存して、同じ計算で比べます。
  • 生の数字より、加工した形で渡します。LLM は数字の大小の判断が得意ではありません。「過去1年の中で上位何%か」のように、位置づけが分かる形にします。
  • 単位をそろえて明記します。個別銘柄のプロンプトで起きた、小数とパーセントの混同を繰り返さないためです。
  • 「先月の事実」と「今後の見通し」を分けます。先月上がったセクターを強気とするだけなら、過去のリターンから計算できるので、LLM もレポートも要りません。
  • 日付が分かる入力を渡すときは、モデルの知識の期限を確認します。
  • 最初は、①値動きと、③のうち金利・VIX だけで始めます。どれも DB か yfinance から機械的に作れて、漏れの心配がありません。

9レポートの作り方

運用会社のレポートをそのまま渡す代わりに、AI に月ごとのレポートを作らせて渡す案です。形式は使いやすいですが、作り方によっては未来の情報が入ります。

試作（2025-01_sector_report.md）で見つかった問題

問題例
対象月より後の情報が入っている「自動車関税は15%で妥結する見通し」とあるが、日米が15%で合意したのは2025年7月。引用にも「2025年の振り返りと2026年の株式市場」（2026年1月）、「2025年プレイバック」（2025年末）、2025年12月の利上げの調査（「利息負担で経常利益が平均1.3%減」の出どころ）、2025年4月の資料が含まれる
その結果、スコアが未来を知っている「自動車：やや強気 +1」は、半年後の結果を知ったうえで付いている
推定で埋めた数字がある東証グロース250の前月末の値が「704.62（推定）」
対象が日本株指数は日経平均と TOPIX、セクターは日本向けの15分類。DB は S&P500 と GICS の11セクター
内容が「その月の振り返り」1月に何が上がったかをスコアにしている。使えるのは2月以降の予想だけ

原因は、AI に今日の時点で検索させたことです。今日の検索は、後から書かれた記事を必ず拾います。

作り方

元の資料を自分で集める

運用会社の月次レポートなど、公表日がはっきりしているものを使う。公表日を記録する。

AI には、その資料だけを渡す

検索はさせない。新しい知識を足させず、渡した文章を整理させるだけにする。

決まった形式で出させる

試作の CSV・JSON の形を、GICS の11セクターに合わせて使う。「先月の事実」と「今後の見通し」を分ける。

引用を機械的に確認する

根拠が渡した資料の中にあるか、資料の公表日が判断日以前かを確認する。何か月分かは、元の資料と読み比べる。

判断日との関係にも注意が必要です。9月の振り返りレポート（10月初めに公表）を9月の予想に使うと、それだけで先読みになります。

12共分散の作り方

方針：判断日までの直近1年の日次リターンで共分散を計算し、毎月更新します。そのうえで、縮小推定で補正します。

毎月、窓を1か月ずつずらして計算し直す方法は「ローリング・ウィンドウ」と呼ばれ、標準的なやり方です。

先読みにならない

使うのは判断日までのデータだけです。

窓が重なっても問題ない

先月と今月で 11/12 のデータが同じです。共分散はゆっくり変わるものなので、推定としてはこれで構いません。

期待リターンには使わない

過去の平均リターンは当てになりません。Black-Litterman は、期待リターンを市場の均衡と LLM の予想から作ります。過去データから取るのは共分散だけです。

最初の月から1年分ある

DB は2023年3月からあるので、最初の判断月（2024年3月）でも1年分を使えます。

注意点

点内容対処
1年分でも足りない日次データは約250個で、銘柄数（約500）より少ない。そのままの共分散行列は最適化に使えない縮小推定（Ledoit-Wolf という定番の方法）で補正する。scikit-learn に入っている
窓の長さ短いと最近の動きに敏感でぶれやすい。長いと安定するが、古い情報が残るまずは単純な1年にする。長さは portfolio_runs に記録し、後で変えて比べられるようにする
上場して1年未満の銘柄分社化などで入った銘柄は、1年分のデータがないある分だけで計算するか、その月は対象から外すかを決める（未定）
元の実装との違い元は、その月の約20日分だけで計算しているレポートに変更点として書く

13月次か四半期か

四半期にしても、共分散の扱いは変わりません。四半期のリターンは1年に4個しかないので、共分散は日次データから計算し、期間の長さに合わせて拡大するだけです。それ以外の違いは次の通りです。

月次四半期
評価できる回数30回10回。差が出ても、偶然と区別しにくい
LLM を呼ぶ回数30か月分3分の1
売買の回数多い少ない。売買コストを考えるなら有利
財務データとの相性新しい決算がない月がある決算が四半期ごとなので合う
途中の変化毎月見直す3か月間、比率と構成銘柄の入れ替えを放置する
  • メインは月次のままにします。評価の回数が3倍あるためです。
  • 四半期は、セクターの予想と財務データを使う段階（段階3）で試します。
  • 中間の形もあります。「毎月見直すが、予想は3か月先」にすれば、評価の回数を30回のまま保てます。ただし、評価の期間が重なります。
  • 四半期にする場合の判断日は、2月末・5月末・8月末・11月末が良いです。暦の四半期末では、直前の四半期の決算がまだ出ていません（次の章）。

テーブルは対応済みです。llm_views は判断日（as_of_date）で回答を区別し、llm_runs に入力の長さと予想の期間を記録するので、月次と四半期の両方が同じテーブルに入ります。

扱い方

  • 基本の条件：判断日ごとに、「filed_date が判断日以前の中で、いちばん新しい四半期」を銘柄ごとに選びます。これで先読みは起きません。
  • 銘柄によってデータの古さが違ってよい：同じ判断日でも、ある銘柄は1か月前の決算、別の銘柄は3か月前の決算になります。実際の投資家も同じ状況です。
  • セクターで合計するとき：「各社の最新の四半期」を足し合わせ、期末日をそろえようとしません。前年の同じ四半期と比べた伸び率にすると、区切りの違いと季節性の両方をならせます。
知っておくこと
  • filed_date は安全側の日付です。正式な報告書（10-Q、10-K）の提出日で、実際にはその数日〜数週間前に決算発表で数字が公表されています。先読みにはなりませんが、市場はもっと早く知っていました。
  • 日数がおかしい値が少しあります。提出が期末より前（最小 -56日）や、1年以上後（最大 423日）の行があります。項目ごとに別の書類の日付を拾っているのが原因と思われます。財務データを使う段階で、件数を調べて除きます。
