読み取れること

  • 入力をほぼなぞっている：予想は「先月の平均」に近い値になります。7月の NVDA は先月が −0.84% だったので、予想も −1.08% とマイナスになりました。
  • プラスに偏りがち：6月時点の予想は5銘柄すべてプラスでした。先月がマイナスだった JNJ（−0.06%）もプラスと予想しています。
  • NVDA を大きく外した：+0.57% と予想しましたが、実際は −0.84% でした（2024年7月のハイテク株の調整）。ただし予想のばらつきも5銘柄で一番大きく、Black-Litterman では「自信のないビュー」として弱めに扱われます。
  • 符号は5銘柄中4銘柄で当たりましたが、全部プラスと予想した結果にすぎず、5銘柄では予測力の判断はできません。

6Black-Litterman まで通してみる（5銘柄のおもちゃ版）

出力が後続処理に使えるかを見るため、evaluate_multiple.py の black_litterman_LLM() にそのまま渡しました。6月のデータでウェイトを決め、7月の実績で評価しています。

最初の結果：ウェイトが全銘柄 20.0%（等ウェイトと完全に同じ）。最適化が1回で「収束した」と判断して止まり、初期値から動いていませんでした。5銘柄だと目的関数の値が 0.0002 程度と小さく、SciPy の初期設定の収束判定（ftol = 1e-6）にすぐ引っかかるためです。元論文の約500銘柄の結果ではウェイトが動いていたので、少数銘柄で起きやすい問題ですが、本番でも注意が必要です。

収束判定を厳しく（ftol=1e-12）した結果が下の表です。市場均衡リターン Π の計算で、元コードどおり年率 2% を日次リターンから引いた場合と、日次に直した 2%/252 を使った場合の2通りを比べています。

  • 元コードどおりだと Π がおかしい：AAPL と NVDA の Π が −1.4%/日、−2.9%/日 と、ありえない大きさのマイナスになります。日次リターンから年率 2% をそのまま引いているためです。
  • 事後リターンはビューに引っ張られる：LLMのビュー（ばらつきが小さく自信あり）の影響が強く、Π がおかしくても、事後リターンは +0.04〜0.14%/日 の範囲に収まっています。
  • 5銘柄・1か月の結果なので、成績の良し悪しは判断できません。計算が最後まで通ることの確認として見てください。

yfinance/returns_*.csv
修正済み

Wikipedia の取得が 403 エラー。User-Agent ヘッダーを付けて解決しました。

run.py
要修正

月末日のデータが欠ける。yfinance の end は「その日を含まない」ので、7月のデータが 7/30 で終わり、7/31 が入っていません。月初日のリターンも pct_change() で消えるため、7月は本来22営業日のところ20日分しかありません（元論文も同じ）。

run.py の yf.download
要修正

最適化が初期値で止まることがある。目的関数の値が小さいと、SLSQP が1回で止まり等ウェイトのままになります。options={"ftol": 1e-12} などの指定がおすすめです。

evaluate_multiple.py / baselines.py
要確認

市場均衡リターン Π の単位の不一致（前回の解説で指摘した点）が、実際の数値でも確認できました。

evaluate_multiple.py
補足

プロンプトの単位が曖昧。プロンプトでは「percentage change」と書いていますが、入力も出力も小数（0.003 ＝ 0.3%）です。GPT は入力に合わせて小数で答えていましたが、モデルによっては「0.3」と答える恐れがあります。
