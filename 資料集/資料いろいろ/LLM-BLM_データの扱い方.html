4株価と株式分割の扱い

問題：yfinance の値は、種類によって「調整の有無」がバラバラ

株式分割（1株を複数株に分けること）や配当があると、過去の株価をどう見せるかで値が変わります。yfinance で調べたところ、値の種類ごとに扱いが違いました。

yfinance の値株式分割配当NVIDIA 2024-06-06（分割前）の値DB での扱い
Close（調整前の終値）調整済み調整なし121.00 ドル（当時の実際の株価は約 1,210 ドル）prices.close
Adj Close（調整後終値）調整済み調整済み120.65 ドルprices.adj_close
発行済み株式数調整なし―24.6 億株（分割後は 246 億株）今の基準に直してから shares_outstanding

NVIDIA は 2024-06-10 に1株を10株に分割しました。株価は分割で調整済みなのに、株式数は報告どおりの値です。そのまま掛け算すると、分割前の時価総額が10分の1になってしまいます。

解決：DB に入れる前に、すべて「今の分割基準」に揃える

時価総額 ＝ close × shares 株価も株式数も、取得した日（2026年）の分割基準に揃えて保存しているので、単純な掛け算で求まる

株式分割をしても会社の価値（時価総額）は変わらないので、株価と株式数が同じ基準なら、どの基準で掛け算しても答えは同じです。

当時の基準： 1,210 ドル × 24.6 億株 ＝ 約 3 兆ドル
今の基準  ：   121 ドル × 246  億株 ＝ 約 3 兆ドル（同じ）

yfinance の株価はもともと今の基準なので、株式数のほうを今の基準に直してから DB に入れます。この処理は marketdb/build_db.py で、取り込むときに1回だけ行います。

第2版からの変更：分割のテーブルをやめた理由

第2版：splits テーブルで補正

株式数は報告値のまま保存し、分割の履歴を splits テーブルに持って、時価総額を計算するたびに SQL で補正していました。SQL が複雑になり（分割比率の積を求めるサブクエリが必要）、テーブルも1つ多くなります。

第3版：取り込む前に揃える

補正は取り込むときに Python で1回だけ行い、DB の中は全部同じ基準にしました。テーブルが7つに減り、時価総額は close × shares だけで出せます。

この方式が安全なのは、「全期間を1回で取得して固定する」と決めたからです。後から追加で取得する運用だと、取得時期ごとに分割の基準がずれていきます。研究期間（2024-04〜2026-03）はすでに過去なので、その心配はありません。

リターンの計算には adj_close を使う

リターンは配当も含めて考えるのが一般的なので、adj_close を使います。これまで run.py が使っていた値と完全に同じなので、LLM に渡すデータは変わりません。時価総額に close を使うのは、adj_close だと配当の多い銘柄ほど過去の時価総額が数%小さくなるためです。

株価は「1回取ったら固定」

調整後の値は、配当や分割があるたびに過去の分までさかのぼって書き換わります。途中で取り直すと、古い基準と新しい基準の値が混ざる恐れがあります。そのため、全期間を1回でまとめて取得し、その後は上書きしない（INSERT OR IGNORE）ことにしました。

種類株の会社（Alphabet、Fox、News Corp）

フラグにした場合

tickers に「現在メンバーか」のフラグを持たせると、今の状態しか分からず、「2024年6月時点のメンバー」が答えられません。日付×銘柄ごとにフラグを持たせると約27万行になり、同じ情報の繰り返しになります。

採用した持ち方

index_changes に Wikipedia の入れ替え履歴をそのまま入れ、そこから index_membership（銘柄ごとの在籍期間）を作ります。銘柄1つにつき、基本は1行で済みます。

index_membership の例
  symbol   start_date   end_date
  AAPL     NULL         NULL          ← 期間の前から在籍し、今も在籍
  PLTR     2024-09-23   NULL          ← 途中で追加
  AAL      NULL         2024-09-23    ← 途中で除外

ある日のメンバーを取り出す SQL

SELECT symbol FROM index_membership
WHERE (start_date IS NULL OR start_date <= '2024-06-03')
  AND (end_date   IS NULL OR end_date   >  '2024-06-03');

テストでは、「2024-06-03 には在籍、2024-09-01 に除外」とした銘柄が、6/3 の結果には含まれ、10/1 の結果には含まれないことを確認しました。

限界：除外された銘柄の一部は株価が取れない

2024年6月〜2025年1月に除外された11銘柄のうち、買収などで上場廃止になった 4銘柄（Catalent、Marathon Oil、Qorvo、Comerica）は yfinance にデータがありませんでした。無料のデータでは完全には再現できないので、取れなかった銘柄の数と割合をレポートに書きます。

ティッカーは最新のもので統一

旧ティッカーは yfinance で取れないか、別の銘柄に再利用されていることがあります（例：旧 Paramount の PARA は、今は別の銘柄の株価が返ります）。そのため、DB のティッカーはすべて最新のものにしています。入れ替え履歴に旧ティッカーで載っている銘柄は、対応表（build_db.py の TICKER_ALIASES）で変換します。

入れ替え履歴を取得 → index_changes

Wikipedia「Historical components of the S&P 500」の全履歴（412 件）。ティッカーは最新の yfinance の書き方に変換します。

在籍期間を再現 → index_membership、tickers

今の構成銘柄から入れ替えを新しい順に取り消し、期間中に在籍した 568 銘柄の在籍期間を作ります。食い違いがあれば表示し、手で TICKER_ALIASES（今は SATS → ECHO の1件）に追加します。

株価を取得 → prices

全銘柄と S&P500 指数を、期間全体でまとめて1回取得します。株価が1日分もない銘柄は除外します。

株式数を取得 → shares_outstanding

報告値を今の分割基準に直し、外れ値を捨て、1日1つ（中央値）にします。種類株の会社は比率で振り分けます。期間外は「期間初日に有効な報告」1件だけ残します。

不完全な銘柄を除外

在籍期間の半分以上で株価がない銘柄（ティッカーの再利用）と、半分以上で株式数がない銘柄（ティッカー変更）に除外理由を付け、株価と株式数を削除します。

確認用の表示

在籍期間中の株価の欠け、1日で50%を超える値動き（別銘柄の混入の手がかり）を表示します。今回見つかった急な値動き（MRNA +177% など 7 件）は、いずれも実際の出来事によるものでした。

build_db.py の全文
"""
Build the SQLite database for the study period (DB_START_DATE .. DB_END_DATE in .env).

    python marketdb/build_db.py

Steps (each one is skipped when its table already has rows, so stored data is never refetched):
  1. S&P500 constituent changes (Wikipedia)          -> index_changes
  2. membership periods and tickers                  -> index_membership, tickers
  3. daily prices of every member and ^GSPC          -> prices  (no data -> tickers.excluded_reason)
  4. shares outstanding on the current split basis   -> shares_outstanding
  5-6. members without prices or shares for most of their membership are excluded
     (tickers.excluded_reason) and their prices / shares are deleted
  7. sector of stocks that left the index (old Wikipedia revisions) -> tickers.gics_*
  8. indices listed in INDEX_TICKERS that are not stored yet           -> prices

Tickers are stored as the latest yfinance tickers ('BRK-B', not 'BRK.B'): old tickers often
fail on yfinance or now point to another company.
"""
import sys
from concurrent.futures import ThreadPoolExecutor
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1]))

import pandas as pd

from marketdb import config
from marketdb.sources.prices import download_prices
from marketdb.sources.shares import class_ratios, download_shares_and_splits
from marketdb.sources.universe import load_index_changes, load_sp500_table, load_sp500_table_at, to_yf_symbol
from marketdb.transform.membership import build_membership
from marketdb.transform.shares import clip_to_period, to_current_split_basis
from marketdb.db.connection import connect, init_db
from marketdb.db.index import save_index_changes, save_membership
from marketdb.db.market import fill_gics, mark_excluded, missing_tickers, save_prices, save_shares, save_tickers

# Tickers that changed after the change was recorded on Wikipedia (old -> latest)
TICKER_ALIASES = {
    'SATS': 'ECHO',  # EchoStar: added on 2026-03-23 as SATS, now listed as ECHO
}
INDEX_TICKERS = [
    ('^GSPC', 'S&P 500 Index'),
    ('^IRX', '13 Week Treasury Bill Yield (percent per year, used as the risk-free rate)'),
]
# Companies with several share classes in the index: yfinance reports the company-wide share count
# for each class, so it is split by the current class ratio (otherwise the company is counted twice)
MULTI_CLASS = [('GOOGL', 'GOOG'), ('FOXA', 'FOX'), ('NWSA', 'NWS')]

START, END = config.DB_START_DATE, config.DB_END_DATE


def is_empty(conn, table):
    return conn.execute(f"SELECT COUNT(*) FROM {table}").fetchone()[0] == 0


def step_index_changes(conn):
    changes = load_index_changes()
    for col in ['added_symbol', 'removed_symbol']:
        changes[col] = changes[col].map(lambda s: to_yf_symbol(s, TICKER_ALIASES) if s else None)
    save_index_changes(conn, changes)
    print(f"[1] index_changes: {len(changes)} rows")


def step_membership(conn):
    current = load_sp500_table()
    current['symbol'] = current['Symbol'].map(lambda s: to_yf_symbol(s, TICKER_ALIASES))
    changes = pd.read_sql("SELECT date, added_symbol, added_name, removed_symbol, removed_name FROM index_changes", conn)
    periods, issues = build_membership(current['symbol'], changes, START, END)

    names = {}
    for _, r in changes.iterrows():
        for s, n in [(r['added_symbol'], r['added_name']), (r['removed_symbol'], r['removed_name'])]:
            if isinstance(s, str):
                names[s] = n
    gics = {r['symbol']: (r['Security'], r['GICS Sector'], r['GICS Sub-Industry']) for _, r in current.iterrows()}
    symbols = sorted({s for s, _, _ in periods})
    save_tickers(conn, [(s, *gics[s]) if s in gics else (s, names.get(s, s), None, None) for s in symbols])
    save_tickers(conn, [(s, name, None, None) for s, name in INDEX_TICKERS])
    save_membership(conn, periods)

    n_start = sum(1 for _, st, en in periods if st is None or st <= START)
    print(f"[2] tickers: {len(symbols)} stocks + {len(INDEX_TICKERS)} index | membership periods: {len(periods)} "
          f"| members on {START}: {n_start}")
    for issue in issues:
        print(f"    ! {issue}  -> add it to TICKER_ALIASES")


def step_prices(conn):
    symbols = [r[0] for r in conn.execute("SELECT symbol FROM tickers ORDER BY symbol")]
    prices = download_prices(symbols, START, END)
    save_prices(conn, prices)
    got = set(prices['Adj Close'].dropna(axis=1, how='all').columns)
    missing = [s for s in symbols if s not in got]
    mark_excluded(conn, missing, 'no price data on yfinance (delisted)')
    print(f"[3] prices: {len(got)} tickers, {conn.execute('SELECT COUNT(*) FROM prices').fetchone()[0]} rows "
          f"| excluded (no data): {len(missing)} {missing}")


def step_shares(conn):
    symbols = [r[0] for r in conn.execute(
        "SELECT symbol FROM tickers WHERE excluded_reason IS NULL AND symbol NOT LIKE '^%' ORDER BY symbol")]
    # one year before START so that a value exists on the first day
    since = (pd.Timestamp(START) - pd.DateOffset(years=1)).strftime('%Y-%m-%d')
    until = (pd.Timestamp(END) + pd.Timedelta(days=1)).strftime('%Y-%m-%d')

    def fetch(symbol):
        try:
            shares = to_current_split_basis(*download_shares_and_splits(symbol, since, until))
            return symbol, clip_to_period(shares, START, END), None
        except Exception as e:
            return symbol, None, str(e)[:80]

    ratio = {s: r for classes in MULTI_CLASS for s, r in class_ratios(classes).items()}
    failed = []
    with ThreadPoolExecutor(max_workers=4) as pool:
        for i, (symbol, shares, error) in enumerate(pool.map(fetch, symbols), 1):
            if shares is None or shares.empty:
                failed.append((symbol, error or 'no data'))
            else:
                save_shares(conn, symbol, (shares * ratio[symbol]).round().astype('int64') if symbol in ratio else shares)
            if i % 100 == 0:
                print(f"    {i}/{len(symbols)}")
    print(f"    share classes split by: { {k: round(v, 3) for k, v in ratio.items()} }")
    print(f"[4] shares_outstanding: {len(symbols) - len(failed)} tickers, "
          f"{conn.execute('SELECT COUNT(*) FROM shares_outstanding').fetchone()[0]} rows | no shares data: {failed}")


def _exclude(conn, symbols, reason):
    """Mark as excluded and delete their prices and shares."""
    if symbols:
        mark_excluded(conn, symbols, reason)
        marks = ','.join('?' * len(symbols))
        conn.execute(f"DELETE FROM prices WHERE symbol IN ({marks})", symbols)
        conn.execute(f"DELETE FROM shares_outstanding WHERE symbol IN ({marks})", symbols)
        conn.commit()


def exclude_without_member_prices(conn, min_coverage=0.5):
    """Exclude members whose prices cover less than min_coverage of their membership days.
    A delisted ticker can be reused by another security, so prices may exist only outside the membership."""
    rows = conn.execute("""
        SELECT m.symbol,
               (SELECT COUNT(*) FROM prices p WHERE p.symbol = m.symbol
                  AND (m.start_date IS NULL OR p.date >= m.start_date) AND (m.end_date IS NULL OR p.date < m.end_date)) AS n,
               (SELECT COUNT(*) FROM prices g WHERE g.symbol = '^GSPC'
                  AND (m.start_date IS NULL OR g.date >= m.start_date) AND (m.end_date IS NULL OR g.date < m.end_date)) AS days
        FROM index_membership m JOIN tickers t USING (symbol)
        WHERE t.excluded_reason IS NULL""").fetchall()
    symbols = [s for s, n, days in rows if days and n < days * min_coverage]
    _exclude(conn, symbols, 'no price data during membership (ticker reused by another security)')
    print(f"[5] excluded (no prices during membership): {symbols}")


def exclude_without_shares(conn, max_missing=0.5):
    """Exclude members that have no shares report for more than max_missing of their membership days
    (renamed tickers often keep only the history after the rename). Their prices and shares are deleted."""
    rows = conn.execute("""
        SELECT m.symbol,
               SUM(NOT EXISTS (SELECT 1 FROM shares_outstanding s WHERE s.symbol = p.symbol AND s.date <= p.date)) AS missing,
               COUNT(*) AS days
        FROM index_membership m JOIN tickers t USING (symbol)
        JOIN prices p ON p.symbol = m.symbol
         AND (m.start_date IS NULL OR p.date >= m.start_date) AND (m.end_date IS NULL OR p.date < m.end_date)
        WHERE t.excluded_reason IS NULL
        GROUP BY m.symbol""").fetchall()
    symbols = [s for s, missing, days in rows if missing > days * max_missing]
    _exclude(conn, symbols, 'no shares history on yfinance (ticker changed)')
    print(f"[6] excluded (no shares history): {symbols}")


def step_index_prices(conn):
    """Indices added to INDEX_TICKERS after the database was built are fetched here."""
    save_tickers(conn, [(s, name, None, None) for s, name in INDEX_TICKERS])
    missing = missing_tickers(conn, [s for s, _ in INDEX_TICKERS], START, END)
    if missing:
        save_prices(conn, download_prices(missing, START, END))
    print(f"[8] index prices added: {missing}")


def fill_missing_gics(conn):
    """Stocks that left the index are not on the current Wikipedia page, so their sector is read from
    older revisions of the page (newest first: the classification closest to today is kept)."""
    def missing():
        return {r[0] for r in conn.execute(
            "SELECT symbol FROM tickers WHERE gics_sector IS NULL AND symbol NOT LIKE '^%'")}

    before = missing()
    # every quarter, plus the first day of the period for stocks that left right after it
    dates = [*pd.date_range(START, END, freq='QS').strftime('%Y-%m-%d')[::-1], START] if before else []
    for date in dates:
        if not missing():
            break
        table = load_sp500_table_at(date).dropna(subset=['GICS Sector'])
        fill_gics(conn, [(to_yf_symbol(r['Symbol'], TICKER_ALIASES), r['GICS Sector'], r['GICS Sub-Industry'])
                         for _, r in table.iterrows()])
    print(f"[7] GICS filled from old Wikipedia revisions: {len(before) - len(missing())} | still missing: {sorted(missing())}")


def report(conn):
    """Checks that need a human look (nothing is changed here)."""
    print("\n[check] members whose prices do not cover their membership period:")
    rows = conn.execute("""
        SELECT m.symbol, COALESCE(m.start_date, ?) AS s, COALESCE(m.end_date, ?) AS e,
               (SELECT COUNT(*) FROM prices p WHERE p.symbol = m.symbol
                  AND p.date >= COALESCE(m.start_date, ?) AND p.date < COALESCE(m.end_date, '9999')) AS n,
               (SELECT COUNT(DISTINCT date) FROM prices
                  WHERE date >= COALESCE(m.start_date, ?) AND date < COALESCE(m.end_date, '9999')) AS days
        FROM index_membership m JOIN tickers t USING (symbol)
        WHERE t.excluded_reason IS NULL""", (START, END, START, START)).fetchall()
    for symbol, s, e, n, days in rows:
        if days and n < days * 0.99:
            print(f"    {symbol}: {n}/{days} days ({s} .. {e})")
    print("[check] daily moves over 50% (a reused ticker would show up here):")
    big = conn.execute("""
        SELECT symbol, date, r FROM (
          SELECT symbol, date, adj_close / LAG(adj_close) OVER (PARTITION BY symbol ORDER BY date) - 1 AS r FROM prices)
        WHERE ABS(r) > 0.5 ORDER BY ABS(r) DESC""").fetchall()
    for symbol, date, r in big:
        print(f"    {symbol} {date}: {r:+.0%}")


def main():
    conn = connect(config.DB_PATH)
    init_db(conn)
    print(f"DB: {config.DB_PATH} | period: {START} .. {END}")
    for table, step in [('index_changes', step_index_changes), ('index_membership', step_membership),
                        ('prices', step_prices), ('shares_outstanding', step_shares)]:
        if is_empty(conn, table):
            step(conn)
        else:
            print(f"skip: {table} already has data")
    exclude_without_member_prices(conn)
    exclude_without_shares(conn)
    fill_missing_gics(conn)
    step_index_prices(conn)
    report(conn)


if __name__ == "__main__":
    main()

項目内容

提出日（filed_date）その数字が公表された日。期末から提出までは中央値 34 日（9割が 23〜57 日）。分析で使うときは、期末日ではなく提出日以降に使えるものとして扱う

EDGAR はティッカーではなく会社番号（CIK）でデータを持っています。568 銘柄のうち 565 銘柄で番号が分かりました。

  • 手で指定（2銘柄）：Dayforce（DAY）と Warner Bros. Discovery（WBD）は、EDGAR の登録情報で社名を確認して指定しました。
  • 会社番号が変わった会社（5社）：持株会社への移行などで番号が変わった会社は、新旧両方の番号のデータを合わせています（ExxonMobil、BlackRock、Bunge、Ferguson、Skydance〔旧 Paramount Global〕）。

四半期の値の作り方（ビュー fundamentals_quarterly）

EDGAR の値は、そのままでは四半期ごとに揃っていません。ビューで次のように整えています。

3か月分の値を選ぶ

損益計算書の項目は、3か月分の値と期初からの累計の両方が報告されます。3か月分（80〜120日）の値があれば、それを使います。12週や16週で区切る会社（PepsiCo など）も含められる幅にしています。

累計から引き算で求める

第4四半期は単独で報告されないので、「通期 − 9か月累計」で求めます。キャッシュフローは累計だけが報告されるので、「今回の累計 − 1つ前の累計」で求めます。

項目名のゆれを吸収する

同じ「売上高」でも、会社によって使うタグが違います。項目ごとに候補のタグを優先順位つきで並べ、最初に値があるものを使います（売上高は5種類のタグが候補）。

貸借対照表の項目を合わせる

総資産や株主資本は、四半期の末日時点の値をそのまま使います。

  • 不一致は主に定義の違いです。金融機関の売上高（何を売上とみなすかが決まっていない。例：Huntington Bancshares）、少数株主や優先株の扱いによる純利益の違い（Invesco、Simon Property）などです。
  • 「四半期なし」は、最新の四半期が EDGAR の一括データにまだ入っていないものです。全体では約 65 銘柄で、2026年4〜6月期が未収録です（報告書は提出済みなので、後日取り直せば入る見込み）。

使うときの注意

  • 先読みを避ける：ある日に使えるのは、filed_date がその日以前の行だけです。
  • 修正後の数字ではない：最初に提出された値なので、後で修正再表示された数字とは違うことがあります。yfinance などの「最新の値」と合わない場合の原因の1つです。
  • 第4四半期の1株利益は近似：「通期 − 9か月累計」で求めているので、期中に株式数が大きく変わった会社では、実際の第4四半期の値と少しずれます。
  • 金融機関の売上高は目安：銀行や保険は「売上高」にあたるタグが会社ごとに違い、ビューの値が小さめに出る会社があります。
  • 決算期は会社ごとに違う：四半期の末日は、3月・6月・9月・12月の月末とは限りません（Apple は9月下旬が年度末）。銘柄をまたいで比べるときは、filed_date を基準に揃えるのが安全です。
  • PER などの株価指標は保存していない：過去の値はどこからも取れないので、必要になったら株価とこのデータから計算します。

取得は python marketdb/build_fundamentals.py で行います。取得済みの銘柄はスキップするので、途中で止まっても再実行できます。

13レポートに書くときの注意点

そのまま使える形で、書き方の例をまとめます。数値は 2026-10-10 に作った DB のものです。

① データの出どころと期間
「株価と発行済み株式数は yfinance から、S&P500 の構成銘柄と入れ替え履歴は Wikipedia から、2026年10月10日に取得した。期間は 2023-03-01 から 2026-09-30（900 営業日）である。」
② 構成銘柄（その時点の銘柄を使ったこと）
「各時点の構成銘柄は、現在の構成銘柄から入れ替え履歴（期間中 74 件）をさかのぼって再現した。これにより、後から指数に追加された銘柄を過去にさかのぼって保有する先読みを避けている。」
③ 除外した銘柄と生存者バイアス
「期間中に在籍した 568 銘柄のうち、上場廃止などで株価または株式数が取得できない 28 銘柄を除外した。除外には 2023年に破綻した銀行3行と、買収された銘柄が含まれるため、結果には生存者バイアスがある。除外は全戦略に共通して適用した。」
④ 構成比率（時価総額加重）が近似であること
「時価総額は終値と発行済み株式数の積で求め、浮動株による調整は行っていない。したがって、本研究の時価総額比率は S&P500 の公式な構成比率とは一致しない。この比率から作った指数と実際の S&P500 指数の日次リターンの相関は 0.9997、期間全体の騰落率は +94.1% と +93.6% であった。」
⑤ リターンと配当
「個別銘柄のリターンは、株式分割と配当を調整した終値から計算した（配当込み）。比較対象の S&P500 指数（^GSPC）は配当を含まない価格指数であるため、戦略のリターンは指数に対して配当の分（年1.5〜1.7%）だけ有利に見える点に注意が必要である。」
⑥ LLM に渡す情報
「LLM に渡す社名とセクターは 2026年10月時点のもの（指数から外れた銘柄のセクターは、外れる前のもの）であり、当時の名称・分類とは異なる場合がある。」
⑦ LLM の予想の集め方
「各月の最終取引日に S&P500 に在籍する銘柄について、その月の日次リターンと社名・業種を gpt-4o-mini-2024-07-18（temperature 1.0）に与え、翌月の平均日次リターンを 30 個生成させた。30 個の平均をビュー、分散をその不確かさとした。元の実装とは、1回のリクエストで 30 個の回答を得た点、プロンプトでリターンの単位（小数）を明示した点、各月末時点の構成銘柄を対象にした点が異なる。」
⑧ 財務諸表データ（使う場合）
「財務データは SEC EDGAR の XBRL データから取得し、各決算期について最初に提出された値を用いた。各数値は提出日以降にのみ利用可能として扱い、先読みを避けた。」

書くときに気をつけること

  • 「S&P500 の構成比率」とは書かない。「時価総額比率（浮動株調整なし）」や「S&P500 構成銘柄の時価総額加重」と書きます。
  • 戦略と ^GSPC を比べるときは、配当の扱いを揃える。戦略側を close（配当なし）で計算するか、配当の差があることを明記します。
  • 指数に勝った・負けたの差が年1%未満なら、データの近似による差（年 0.7% 程度まで確認済み）と区別できないと考えます。
  • 2023年3〜5月を含む結果は、破綻銀行が入っていないことに触れます。
  • 株価の水準を引用しない。DB の株価は今の分割基準の値で、当時の実際の株価ではありません。
  • 取得日を書く。yfinance の調整後の値は取得時期で変わるので、2026-10-10 取得と明記します。
