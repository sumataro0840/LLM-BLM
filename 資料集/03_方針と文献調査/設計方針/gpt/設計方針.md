## 1. 結果から引き出す前提

1. **LLM に銘柄別リターンを直接予想させる構成は打ち切る。** 数値予想の 81% は入力月の値動きで説明され、その成分を除いた IC は -0.004、95% 区間も +0.027 以下だった。少なくとも現行の質問とモデルには、実用的な固有情報がない。
2. **BLM は情報を作らない。** Ω を較正し、Σ に比例させ、TE を制限すれば計算は意図どおり動くが、情報のない置換ビューとの成績差は確認できなかった。BLM は予測器ではなく、既に検証された信号を安全に比率へ変換する道具として扱う。
3. **相対ビューだけでは系統的な傾きを除けない。** LLM が直近の値動きを銘柄間でもなぞるため、高ベータへの傾きが残った。水準の中心化と、ベータ・セクターなどへの中立化は別に必要である。
4. **LLM の回答間分散を Ω の大きさに使えない。** 外れの大きさを約 5～8 分の1に過小評価する。一方、外れやすさの順位とは関係があったため、補助的な相対尺度として使える可能性は残る。
5. **残された候補は文章からの構造化情報抽出である。** 決算発表文の点数は直近リターンのなぞりが弱く、探索的 IC は +0.033 だった。ただし数値統制後の係数は有意でなく、「文章を読む LLM が追加情報を持つ」とはまだ言えない。
6. **30 か月の月次評価では検出力が足りない。** IC 0.03 程度の効果を評価するには、月数を待つより、決算発表ごとのイベント評価で観測を増やす方が現実的である。ただし同日イベントや期間重複を独立観測として扱ってはならない。
7. **複雑化は改善を保証しない。** 成績フィードバックは楽観を強め、SLSQP は入力の微差で解が変わった。今後は固定仕様、単純な対照、安定した凸最適化を優先する。

## 2. 研究の問いの立て直し

**主な問い**は、次のように変更する。

> 判断時点で公表済みの決算発表文から固定された LLM が抽出した特徴は、価格・財務数値および LLM を使わない文章モデルを超えて、発表後リターンに関する時点外の追加情報を持つか。

これは「LLM は翌月リターンを当てられるか」ではなく、「LLM にしか取り出せない文章情報があるか」を問う。現行結果で否定された数値予想を捨て、唯一可能性が残った文章処理を、BLM から切り離して先に検証する。

副次の問いは以下とする。

- 効果は語調、見通し、ガイダンス変更のどこから生じるか。
- 効果は売上・利益成長、直近リターン、規模、セクターなどで説明されないか。
- LLM は辞書法、単語頻度、正則化回帰より優れるか。
- 効果は発表後 1・5・20 取引日のどこに現れ、取引費用控除後にも残るか。
- 信号が確認された場合だけ、BLM が単純な順位ポートフォリオより安全な実装を与えるか。

主張の中心は予測情報の有無とし、ポートフォリオ収益は二次的な結果とする。

## 3. 新しいアーキテクチャ

```text
提出日時つき決算発表文
        │
        ├─ 数値・価格・財務の基準特徴 ─────────┐
        ├─ LLM を使わない文章特徴 ──────────┤
        └─ 固定 LLM による構造化抽出 ────────┤
                                              ▼
                                  時点順の学習・イベント評価
                                              │
                          ┌── 追加情報なし ───┴── 追加情報あり
                          ▼                             ▼
                    LLM を構成から外す          将来期間で再現確認
                                                        │
                                              再現した場合だけ実装
                                                        ▼
                         信号中立化 → 較正 → BLM または単純順位戦略
```

**捨てるもの**

- LLM に翌月リターンの数値を直接答えさせる処理
- 30 回回答の平均をそのまま q、分散を Ω にする処理
- フィードバックによる自己修正
- BLM の成績から逆算してプロンプトや τ を選ぶこと
- SLSQP による不安定な最適化

**残すもの**

- 提出日つき財務データ、時点別構成銘柄、価格、既存の決算発表文と点数
- 時価総額加重を基準とする考え方
- 判断時点以前だけを使う較正、置換対照、取引費用、TE の記録
- Clarabel などで再現可能な凸最適化

**新しく足すもの**

- EDGAR の受付時刻に基づくイベント時点の確定
- 数値モデル、非 LLM 文章モデル、LLM 特徴の三者比較
- 発表後 1・5・20 日のセクター相対リターンによるイベント評価
- 時系列分割、重複期間の除去、日付単位のブートストラップ
- 「信号検証」と「ポートフォリオ実装」の明確な関門

BLM を使う場合も、q は LLM の生回答ではなく、過去データだけで推定した「点数から相対期待リターンへの写像」とする。P はセクター・ベータ中立の相対ビュー、Ω は時点外誤差から較正し、原則として `PΣPᵀ` に比例させる。τ は TE 調整に使わず、TE・能動ベータ・回転率を別の制約で管理する。

## 4. LLM の役割

LLM にさせるのは、決算発表文からの**固定形式の抽出**だけとする。具体的には、語調、将来見通し、ガイダンスの変更、リスクの種類、経営陣が強調した要因を、少数の離散値と短い根拠に変換させる。モデル、版、プロンプト、温度、入力長、欠損処理を固定し、結果を保存する。

次はさせない。

- 株価やリターンの直接予想
- 自分の確信度や Ω の決定
- 過去の運用成績を見た予想修正
- ポートフォリオ比率や売買判断
- 評価結果を見た後の説明項目の追加

LLM を使わない選択肢として、財務・価格特徴だけのモデル、語調辞書、TF-IDF と正則化回帰を必ず並べる。LLM 特徴を追加しても時点外性能が改善しなければ、最終構成から LLM を外す。新しいモデルは評価期間を知っている可能性があるため予測には使わず、設計・コードレビューに限定する。

## 5. 評価の枠組み

**期間と単位**は、既存の 2023 年11月～2026年8月をイベント単位の再分析期間とする。ただし既に結果を見ているため、独立した確認試験とは呼ばない。2026年10月以降の新規発表を、仕様固定後の前向き確認期間とする。主な目的変数は発表後 5 取引日のセクター相対リターン、副次を 1 日と20日とする。

**先読み防止**では、EDGAR 受付時刻から取引可能日を決め、引け後の発表は翌取引日から測る。場中発表で時刻を確定できないものは主分析から除く。財務値は提出済みの初回値だけを使い、特徴量の標準化、文章モデルの語彙、係数推定は学習期間内で行う。20日リターンが重なる分割にはパージと猶予期間を置く。前向き期間はプロンプトとコードのハッシュを保存し、結果確定まで集計しない。

**検出力**は、イベント数ではなく日付・企業内相関を反映したブロック再標本化で事前に推定する。最低限意味のある追加 IC を +0.01 と暫定設定し、得られる標準誤差と最小検出効果を先に報告する。

**対照群**は、数値のみ、非 LLM 文章特徴、両者の組合せ、セクター内・発表日内で LLM 点数を置換した偽信号とする。

**主指標**は、基準モデルで説明した後の残差に対する LLM 特徴の時点外順位 IC とする。副指標は係数、予測損失の改善、上位・下位群の差、費用控除後スプレッドである。主検定は一つに固定し、副次検定は Holm 補正する。点推定が +0.01 以上かつ95%区間の下限が 0 を超えれば成功、区間上限が +0.01 未満なら実質的失敗、それ以外は証拠不足とする。

## 6. 次の実験

1. **イベント時点監査**
   - **問い**：先読みのないイベント標本を作れるか。
   - **方法**：受付時刻、発表文の種類、取引日、価格欠損を照合し、場中・重複・誤添付を分類する。
   - **基準**：主要標本の95%以上で時刻と文書を確定できれば成功。90%未満なら対象や期間を縮小する。
   - **費用・時間**：API 費用なし、1～2週間。
   - **次の判断**：成功時だけイベント検定へ進み、失敗時は月次研究として限界を明記する。

2. **既存点数のイベント再評価**
   - **問い**：既存の LLM 点数は発表後 5 日の追加情報を持つか。
   - **方法**：価格・財務・セクターを統制し、時系列分割した残差 IC、日付ブロック区間、置換分布を計算する。
   - **基準**：前節の +0.01 と信頼区間の基準を用いる。
   - **費用・時間**：API 費用なし、2週間。
   - **次の判断**：失敗なら BLM 実装を行わず、LLM を外す。成功・証拠不足なら次へ進む。

3. **LLM の必要性の除去実験**
   - **問い**：効果は LLM 固有か、単純な文章・数値処理で再現できるか。
   - **方法**：語調辞書、TF-IDF、財務数値、LLM 特徴、およびそれらの組合せを同じ分割で比較する。
   - **基準**：LLM 追加後だけ主指標が改善し、その差の区間が 0 を超えれば成功。単純モデルと同等なら失敗。
   - **費用・時間**：原則無料、2～3週間。
   - **次の判断**：同等なら安価で再現性の高い非 LLM モデルを採用する。

4. **仕様固定後の前向き確認**
   - **問い**：探索済み期間で見えた効果が、新しい決算期にも再現するか。
   - **方法**：2026年10月以降の発表を固定プロンプトで逐次点数化し、2027年2月まで結果を封印する。
   - **基準**：主指標の符号が正で、既存期間との統合区間が 0 を超えれば支持。逆符号または実質的失敗の区間なら棄却。
   - **費用・時間**：API 2,000円以内、暦時間3～4か月、作業約1週間。
   - **次の判断**：再現時だけポートフォリオ段階へ進む。

5. **条件付きの実装比較**
   - **問い**：確認済み信号を BLM に入れる利点は、単純順位戦略より大きいか。
   - **方法**：単純なセクター中立順位戦略と、較正済み q・Ω、事前 TE 2%、能動ベータ 0、回転率制約を持つ BLM を比較する。
   - **基準**：BLM が同程度の信号収益を保ちつつ、実績 TE、最大下落、回転率のいずれかを明確に下げれば成功。
   - **費用・時間**：追加 API なし、1～2週間。
   - **次の判断**：優位がなければ BLM を外し、信号評価だけを研究成果とする。

## 7. やらないこと

- LLM の銘柄別数値予想を別プロンプトで繰り返すこと。既に単純な写しを超えないと判定できている。
- 回答回数、温度、役割設定を多数探索すること。聞き直しの雑音と多重比較が増える。
- 新しいクラウドモデルで過去を予想させること。学習データによる先読みを排除できない。
- 2023年10月以前の文章を匿名化しただけで確認標本とみなすこと。記憶の混入を保証できない。
- τ、TE、Ω、プロンプトをバックテスト収益最大化で選ぶこと。
- 回答間分散をそのまま Ω にすること、対角 Ω で多数のビューを独立扱いすること。
- 資産クラスやセクター予測へ同時に対象を広げること。1人・5か月では検定が分散する。
- 運用会社レポートの追加分析。米国セクターへの情報が乏しく、主な問いに直接答えない。

## 8. リスクと未解決の問い

- 既存期間は既に探索済みであり、前向き期間も短い。最終結果が「証拠不足」になる可能性が高い。
- 同日に多数の企業が発表し、1・5・20日リターンも重なるため、名目イベント数ほど検出力は増えない。
- LLM 点数が売上・利益成長を言い換えただけかもしれない。利用可能なデータにはアナリスト予想との差がなく、真の決算サプライズを完全には統制できない。
- S&P500 在籍銘柄と取得可能な価格に限定され、生存者・選択バイアスが残る。
- gpt-4o-mini の版が廃止される可能性がある。既存応答を保存し、新規期間ではモデル識別子と全応答を記録する必要がある。
- 文章特徴が統計的に有意でも、発表時の価格反応、売買費用、混雑で経済価値が消える可能性がある。
- 文章抽出の価値が確認されても、BLM が最適な実装とは限らない。BLM を使わない結論を同等に受け入れる。
- 91MB の決算本文を含む Git 履歴について、再現性とデータ管理のどちらを優先するかを決める必要がある。
