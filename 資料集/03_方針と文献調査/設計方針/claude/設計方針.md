# LLM-BLM 設計方針（Claude 案）

作成：Claude（claude-opus-5-5）、2026-10-17。`00_依頼.md` と同じ資料をもとに、GPT・Gemini の案を見る前に書いた。ただし Claude はこれまでの実験を自分で行っており、資料に書かれていない細部（コードや中間の数値）も知っている。その点で他の 2 者と条件が同じではない。

## 1. 結果から引き出す前提

1. **LLM に数値のリターンを答えさせる使い方は終わりにする。**予想は入力の写し（決定係数 0.81）で、写しを除いた予測力は IC 0.03 未満だった。プロンプトの工夫（7 つの実験＋フィードバック）でも変わらなかった。
2. **BLM は「価値を作る装置」ではなく「価値を通す弁」である。**Ω を過去の当たり具合で較正し Σ に比例させれば、当たらないビューは自動で採用率 0 になり、害がない。成績はビューの情報で決まり、BLM の設計では作れない。だから、研究の重心はビューの元になる信号の側に移す。
3. **いちばんの制約は検出力である。**月次の断面 IC で 30 か月では、IC 0.07 未満の効果は見えない。LLM の信号は、モデルの知識の期限より後でしか評価できない。期間を延ばすか、観測の単位を細かくしない限り、何を試しても「区別できない」で終わる。
4. **文章だけを渡すと、LLM は数字のなぞりから離れる。**決算発表文の点数は直近のリターンとほぼ無相関で、業績の伸びに沿った。探索的には IC +0.033（Newey–West の t 2.32）。今ある候補の中で、追う価値があるのはこれだけである。
5. **ただし「LLM である必要」は確かめていない。**決算発表文の点数を、辞書による語調や小さな金融用の言語モデルと比べていない。比べなければ、LLM の追加の価値は主張できない。
6. **銘柄のビューには、市場の動きの方向（ベータ）が入り込む。**相対ビューでは消えないので、ビューの段階でベータとセクターの方向を取り除く必要がある。
7. **評価の仕組み（較正・TE の上限・置換の対照・Newey–West）は使える。**ここは作り直さずに使い回す。

## 2. 研究の問いの立て直し

**主な問い：企業ごとの文章（決算発表文）から LLM が取り出した判断は、同じ時点で手に入る数値の情報と、LLM を使わない単純な文章の分析を超えて、その後のリターンの情報を持つか。**

副次の問い：

- (a) その判断は、発表日ごとに見たとき、発表直後の値動きにすでに織り込まれた部分を除いても残るか（発表後のドリフト）。
- (b) 情報のない信号と、既知の強さの信号を入れたとき、較正した BLM は正しく「入れない／入れる」を判断するか（BLM を安全な採用の仕組みとして示す）。
- (c) LLM の知識の期限より前の文章を使ってよい条件はあるか（匿名化で記憶の影響を測る）。

この問いにする理由：数値の予想は否定され、市場全体の文章（月次レポート）は全銘柄に同じで銘柄の差を作れない。残る「銘柄ごとの文章」は、LLM の強みが出る可能性があり、先行研究とも合い、しかもイベントの単位で観測の数を増やせる。

## 3. 新しいアーキテクチャ

```
[データ層]  marketdb（既存、そのまま）  ＋ イベントの記録（新）
              株価・財務・構成銘柄       決算発表文、受理時刻、発表日
                     │                         │
[信号層]   数値の信号（統計）            文章の信号
           モメンタム、成長率、          ├ LLM（gpt-4o-mini、匿名化した本文、構造化された点数）
           品質、発表直後の反応          ├ LLM を使わない対照（辞書の語調、FinBERT をこの PC の GPU で）
                     │                   └ 知識の期限が古いローカルの LLM（期間の延長用）
                     ▼                         ▼
[信号の検査]  イベント研究（発表後 2〜60 日の超過リターン）／月次の IC
              数値の統制、置換、Newey–West、既知の強さの合成信号での検出力の測定
                     │  ← ここを通った信号だけが先に進む（関門）
                     ▼
[ビューへの変換]  順位 → 正規の点数 → Grinold（α = IC·σ·z）、ベータとセクターの方向を除く
                     ▼
[BLM と最適化]   Π = δΣw、Ω ∝ Σ、採用率 = 判断日より前の較正の傾き（誤差で縮める）
                 Clarabel、TE の上限、能動ベータ 0、片道 0.1% のコスト
                     ▼
[評価]           置換の対照、コスト控除後、TE、IR、回転率、前向きの記録との突き合わせ
```

- **捨てるもの**：LLM の数値予想、回答のばらつきを Ω にする方法、P = I の絶対ビュー、元論文の計算（SLSQP）の追試、予想役へのフィードバック、月次レポートの読み取り。
- **残すもの**：DB と「判断日までの情報だけを使う」決まり、`blm/calibration.py`、TE つきの最適化、バックテスト、置換の対照、LLM の呼び出しの記録。
- **足すもの**：イベントの記録とイベント研究の部品、信号を登録して同じ検査にかける仕組み（DB のテーブル）、合成信号による検出力の測定、本文の匿名化、ローカルの LLM と FinBERT の実行、ビューのベータ・セクター中立化。

## 4. LLM の役割

- **させること**：銘柄ごとの文章から、決まった形の判断（ガイダンスの変更、見通し、語調、リスクの種類）を取り出す。点数は「記録して当たり具合を測れる」形にする。
- **させないこと**：数値のリターンや確率の予想、信頼度の自己申告、Ω や重みの決定、成績のフィードバックを受けた予想の修正。数字は渡さない。
- **使わない選択肢との比較を、研究の中心に置く。**LLM の点数を、(1) Loughran–McDonald の辞書の語調、(2) FinBERT（ローカル、無料）、(3) 数値だけの統計モデル、と同じ出来事で比べる。LLM がこれらを超えなければ、「この用途では LLM は要らない」が結論になる。それも成果として報告する。

## 5. 評価の枠組み

- **主な単位をイベント（決算発表）にする。**発表ごとに、受理時刻の翌取引日から 2〜5 日、2〜20 日、2〜60 日の超過リターン（市場とセクターを引く）を見る。発表当日と翌日の反応は、すでに織り込まれた分として統制に入れる。5,429 件で、月次の断面より検出力が大きい。日付ごとの相関は、日付でまとめた標準誤差で扱う。
- **未来の情報**：受理時刻の翌取引日から測る。知識の期限より後の文章だけを主な分析に使う。期限より前を使う場合は、匿名化したうえで「期限の前と後で当たり具合が変わらない」ことを確かめてから使う。
- **検出力**：既知の IC（0、0.02、0.05、0.10）の合成信号を実データに入れ、どの期間・どの単位なら検出できるかを先に測る。結果を見る前に、必要な効果の大きさを決める。
- **対照群**：情報のない信号（置換）、数値の統制、LLM を使わない文章の分析、ビューなしの時価総額加重。
- **本当の検証用データを残す**：2026 年 10 月〜2027 年 2 月の決算シーズン（約 2 回、1,000 件前後）を、手順を凍結した前向きの検証にする。これは、どのモデルも知らない、まだ誰も見ていないデータである。
- **判定**：実験ごとに主な検定を 1 つ事前に決め、効果の 95% 区間と「意味のある最小の効果」で、支持・不支持・証拠不足を分ける（今回と同じ）。

## 6. 次の実験

**E1：検出力と BLM の働きを、2016〜2026 年の長い期間で測る（LLM なし）**
- 問い：IC がどれだけあれば、30・60・125 か月で検出できるか。較正した BLM は、IC に応じて正しく採用率を上げ下げするか。
- 方法：既知の IC の合成信号と、実際の統計の信号（モメンタム、品質、成長）を、今のバックテストに入れる。置換の対照も同じ期間で。
- 基準：IC 0.05 の合成信号で採用率が 0 より有意に大きくなり、IC 0 では 0 にとどまれば「BLM は安全な採用の仕組み」。
- 費用・時間：0 円、1〜2 週間。
- 次の判断：検出に必要な観測の数が分かり、E2・E3 の規模が決まる。

**E2：決算発表文の点数をイベントの単位で評価し直す**
- 問い：点数は、発表直後の反応と数値（利益の前年比、売上の伸び、直前のリターン）を統制しても、発表後のドリフトを予測するか。
- 方法：既存の 5,429 件の点数を使う。受理時刻から超過リターンを計算し、日付でまとめた標準誤差の回帰。
- 基準：点数の係数が正で p < 0.05 なら次へ。区間の上限が意味のある最小の効果を下回れば打ち切り。
- 費用・時間：0 円（API なし）、1 週間。
- 次の判断：不支持なら、文章の信号の線は「この規模では価値なし」で閉じ、E5 は行わず、E1 の結果と否定的な結論で報告をまとめる。

**E3：LLM と、LLM を使わない文章の分析の比較**
- 問い：同じ出来事で、LLM の点数は辞書の語調と FinBERT を超えるか。
- 方法：E2 と同じイベント研究に、3 つの点数を並べて入れる。
- 基準：LLM の点数が、他の 2 つを統制しても有意に残るか。
- 費用・時間：0 円（FinBERT はこの PC の GPU）、1 週間。
- 次の判断：超えなければ、以後の文章の信号は安い方法で作る。

**E4：期間の延長と、記憶の影響の測定**
- 問い：匿名化した決算発表文（社名・ティッカー・日付・人名を伏せる）なら、知識の期限より前の文章も使えるか。
- 方法：2019〜2023 年の発表文（約 1.2 万件）を取得し、匿名化して gpt-4o-mini で点数化。期限の前と後で、当たり具合と点数の分布を比べる。知識の期限が古いローカルの LLM（例：2022 年までの 7B 級を 4 ビットで）でも同じことをし、2023 年以降の重なる期間で gpt-4o-mini の点数との一致度を測る。
- 基準：期限の前の当たり具合が、後と区別できず、匿名化の前後で点数がほぼ変わらなければ、延長した期間を主な分析に加える。
- 費用・時間：約 15 ドル、2〜3 週間。
- 次の判断：使えれば、検出力が約 2 倍になる。使えなければ、期限より後のデータと前向きの検証だけで結論を出す。

**E5：BLM への組み込み（E2〜E4 で信号が残った場合だけ）**
- 問い：文章の信号を、ベータ・セクター中立のビューとして較正した BLM に入れたとき、置換の対照とコストを超えるか。
- 方法：Grinold の式でビューにし、TE の上限と能動ベータ 0 の制約で、時価総額加重、統計の信号、両方を合わせたもの、と比べる。
- 費用・時間：0 円、1〜2 週間。

これと並行して、**前向きの記録**を今すぐ始める（手順を凍結し、毎週 EDGAR の新しい発表文を取得・点数化して保存する。費用は数ドル）。

## 7. やらないこと

- LLM に数値のリターンを予想させるプロンプトの工夫。7 つの実験で結論が出ている。
- 新しいモデル（gpt-5.x、gemini-3.x）に評価期間の予想をさせること。記憶と区別できない。
- 予想役へのフィードバックの調整。強気に寄る副作用が出た。
- τ や TE の目標を、評価期間の成績で選ぶこと。
- 月次レポートの読み取りの改善。全銘柄に同じ文章で、銘柄の差を作れない。
- 対象の市場や資産クラスを広げること。データの準備に時間がかかり、主な問いに答えない。
- 元論文の結果の再現にこれ以上時間を使うこと。再現できないことは示した。

## 8. リスクと未解決の問い

- 決算発表文の点数が拾っているのは、すでに知られた「発表後のドリフト（PEAD）」かもしれない。アナリストの予想（コンセンサス）は無料で手に入らないので、驚きの大きさを正確には統制できない。発表直後の反応と利益の前年比で代用する。
- 匿名化は完全ではない（数字や製品名から会社が分かる）。記憶の影響は「期限の前後の差」で間接的に測るしかない。
- 古いローカルの LLM は、文章を読む力が弱いかもしれない。
- 前向きの検証は 2 シーズンしかなく、それだけで強い結論は出ない。凍結した手順の記録として価値がある。
- 1 人で 5 か月。E4 は時間がかかるので、E2・E3 の結果しだいで省く。
