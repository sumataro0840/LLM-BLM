# 1. 結果から引き出す前提

これまでの実験結果から、LLM-BLMの設計を根本的に決定づける前提として以下の6点を引き出す。

1. **LLMによる数値リターンの直接予想は無価値である**
   LLMに過去のリターン数値を渡して翌月リターンを予想させても、入力された直近の動きの「なぞり（決定係数0.81）」に過ぎず、写しを除いた固有の予測力（IC）はゼロである（H02）。数値予想のアプローチはここで完全に棄却される。
2. **LLMのビューは、構造的にベータへの傾きを持つ**
   市場が上がった月には高ベータ銘柄が上がり、LLMはそれをなぞるため、予想の相対的な差自体が「高ベータが良い」という形になってしまう。相対ビューに変換してもこの傾きは消えない（H03）。ポートフォリオに入れる前に、ビューからベータの方向を取り除く必要がある。
3. **回答のばらつきをそのまま「不確実性」として使うと破綻する**
   回答の分散をBLMの$\Omega$に設定すると、実際の外れに対して確信過剰（約8倍）となり、比率が極端に集中する。$\Omega$は過去の予測精度（較正の傾き $b_t$）に基づいて$\Sigma$に比例させる形で縮小し、かつトラッキングエラー（TE）の上限を設けることで初めて「安全に何もしない」土台として機能する（H04）。
4. **文章（定性情報）のみを与えれば、LLMは「なぞり」から脱却できる**
   決算発表文などのテキストだけを読ませた場合、直近の値動きとの相関は消え（+0.05）、業績の伸びに沿った独自のスコアを抽出できる（H05, H06）。LLMの強みはここでのみ発揮される。
5. **30か月の月次評価では、予測力を証明するための検出力が絶対的に足りない**
   決算発表文のスコアには予測力の兆し（Newey-West $t=2.32$）が見えたが、30か月という短い期間と月次の観測数では、実用に足る微小な効果（IC 0.03〜0.06程度）を統計的に有意と断定できない。期間の延長か、観測数の大幅な増加が不可欠である。
6. **LLMによる自己フィードバックは逆効果である**
   過去の成績の数値を渡して予測を改善させようとしても、一律に楽観バイアスが強まるだけであり、予測精度は向上しない（H07）。改善プロセスにLLMを使うべきではない。

# 2. 研究の問いの立て直し

**主な問い：**
「LLMが決算発表文から抽出した定性的なスコア（語調、見通し等の変化）は、既存の財務数値や統計モデルでは捉えきれない追加の予測価値（アルファ）を持っているか？」

**副次の問い：**
- その追加の予測価値は、月次のポートフォリオ運用よりも、決算発表直後（1〜20日）の短期的なイベントにおいて顕著に現れるか？
- 知識の期限より前のデータに対して、企業名や数値をマスキング（匿名化）することで、LLMの先読みバイアスを完全に排除しつつ有効な情報を抽出できるか？
- ベータの方向を除去し、当たり具合で較正されたBLMアーキテクチャは、LLMの定性スコアを安全かつ有効にポートフォリオの比率へ変換できるか？

**なぜその問いか：**
第一段階の実験で「LLMに数値を予測させること」「LLMに不確実性を自己申告させること」の無意味さが確定した。一方で、定性的なテキスト情報を構造化し、業績の文脈を読み解く能力にのみ、既存の統計アプローチにはない独自の価値の片鱗が確認された。したがって、「LLMとは数値を回帰するものではなく、文章を解釈する道具である」と割り切り、その定性解釈の精度と、それをポートフォリオに安全に組み込むためのリスクモデル（BLM）の真価を問う形に研究を純化させるべきだからである。

# 3. 新しいアーキテクチャ

現行の「数値を渡して数値を予想させる」構成を捨て、以下のようなアーキテクチャに再構築する。

```text
[テキスト情報] 決算発表文 (8-K EX-99.1)
      │
      ▼
[前処理/匿名化] 企業名・具体数値のマスキング (Phi-3-mini等 / ルールベース)
      │
      ▼
[LLM (gpt-4o-mini)] ※数値データは一切渡さない
      │ 語調・見通し・ガイダンス変更のスコア化
      ▼
[ビューの純化] スコアの相対ビュー化、および銘柄ベータ方向の残差化(直交化)
      │
      ▼
[較正 (統計)] 過去のスコアと結果から傾き $b_t$ を算出、標準誤差で縮小
      │
      ├─── (採用率 $b_t$) ──┐
      │                   ▼
      │              [BLM エンジン]  $\Omega \propto \Sigma$ を適用
      ▼                   │
[数値データ] ───────┼──> [最適化 (ソルバー)] 事前TE上限(3%)・能動ベータ0制約
株価, 財務 (統計モデル)    │
                          ▼
                  [ポートフォリオ比率]
```

*   **現行から捨てるもの：** LLMへの直近リターンや株価の入力、LLMによる直接的なリターンの数値予想、回答の分散をそのまま $\Omega$ にする処理、LLMによるフィードバック。
*   **残すもの：** BLMの枠組み（Clarabelによる最適化、TE上限の制約）、過去の結果から信頼度を測る較正（$b_t$）の仕組み、相対ビューの概念。
*   **新しく足すもの：** 知識期限前のデータに対応するための「テキスト匿名化処理モジュール」、ビューからの「ベータ方向の直交化（残差化）」処理、数値情報のみを用いて比較対照となる「統計モデル」の並行評価。

# 4. LLM の役割

**させること：**
決算発表文などのテキスト情報の解釈に特化させる。具体的には、テキスト全体から「経営陣の語調の強気/弱気」「将来見通しの変化」「ガイダンスの引き上げ/引き下げ」を読み取り、-2〜+2 などの決められた構造化フォーマットでスコアとして抽出させる。

**させないこと：**
リターンやボラティリティなどの「数値」の予測、比率の計算、自身の過去スコアの反省や修正（フィードバックループへの組み込み）、および自分自身の予測に対する自信（分散）の自己申告。これらはすべて統計的枠組み（較正とオプティマイザ）に委ねる。

**使わない選択肢との比較：**
LLMを使わない選択肢として、「Loughran-McDonald等の金融辞書ベースの感情分析モデル」や、単純な「財務数値のモメンタム（統計モデル）」が挙げられる。LLMを用いる理由は、辞書ベースでは捉えきれない文脈（例：「赤字だが市場予測よりはマシだった」「見通しを据え置いたが、語調は極めて自信に満ちている」）を解釈できるかどうかに懸かっている。実験では、これら従来のモデルを対照群とし、LLMの追加的価値を厳密に比較する。

# 5. 評価の枠組み

*   **期間：** 2015年〜2026年の約10年間（約125か月）。これにより、ICやポートフォリオ評価における統計的な検出力を確保する。
*   **未来の情報の混入の防ぎ方：** 
    1. ポイント・イン・タイムの徹底（決算発表の提出日ベースで情報を区切る）。
    2. 先読みバイアス（LLMが2023年10月以前の相場を知っている問題）の防止策として、テキストをLLMに入力する前に、ローカル環境で固有表現抽出（NER）等を用いて企業名、製品名、具体的な財務数値をマスキング（匿名化）する。
*   **検出力：** 月次での評価（N=125か月）に加え、決算発表というイベントごと（N=数万件）の「発表後1日・5日・20日の超過リターン」を評価の軸とする。これにより、微小なアルファ（IC 0.03水準）であっても統計的に有意な検出が可能になる。
*   **対照群：**
    1. 時価総額加重ポートフォリオ（ベースライン）
    2. 数値のみを用いた統計モデル（リッジ回帰やファクターモデル）
    3. LLMのスコアをセクター内でランダムに並べ替えたプラセボ・ビュー（最低200回）
*   **主な指標と判定の決め方：**
    *   **予測の判定：** 財務数値（売上・利益の伸び）を統制した上での、イベント後の超過リターンに対するスコアの回帰係数（Fama-MacBeth回帰）の $t$ 値。Newey-West調整を用いて $t > 1.96$（有意水準5%）であれば、予測力ありと判定。
    *   **ポートフォリオの判定：** 事後TEが目標水準（3〜5%）に収まっているかの監視。プラセボ・ビュー（セクター内順位入れ替え）の超過リターン分布と比較し、片側の経験的 $p$ 値が 0.05 未満であれば、追加の価値を生んだと判定する。

# 6. 次の実験

優先順位の高いものから順に以下の実験を行う。

**1. 決算発表文のイベントスタディ（短期リターンの解像度向上）**
*   **問い：** すでに抽出済みのスコアは、月次ではなく発表直後（1・5・20日後）の超過リターンを予測できるか？
*   **方法：** H06で取得済みの5,429件のスコアを活用。発表直後の市場およびセクターに対する超過リターンを目的変数とし、売上・利益サプライズを統制した回帰分析を行う。
*   **成功と失敗の基準：** 数値を統制したスコアの係数が、Newey-West調整後の $t$ 値で1.96を超えれば成功。
*   **費用と時間の見込み：** API費用0ドル。コード実装を含め数日で完了。
*   **結果による次の判断：** 成功すれば、定性情報が短期的に市場に織り込まれる価値を持つことが確定し、長期拡張（実験3）に自信を持って進む。失敗すれば、LLMのスコアは数値情報を超える価値がない可能性が高まり、研究の主眼をBLMの制約手法に移す。

**2. 過去データのマスキング（匿名化）手法の確立と検証**
*   **問い：** 企業名と数値を伏せたテキストからでも、LLMは元のテキストと同等のスコアを抽出でき、先読みバイアスを防げるか？
*   **方法：** 2024年以降のデータに対し、ローカルLLM（Phi-3-mini等）または正規表現を用いてマスキングを実施。マスキング済みの文章をgpt-4o-miniでスコア化し、元のスコアとの相関およびICを比較する。
*   **成功と失敗の基準：** マスキング前後でのスコアの順位相関が0.7以上を保ち、かつICの低下が誤差の範囲内であれば成功。
*   **費用と時間の見込み：** ローカル処理と少量のAPIテストで約1〜2ドル。約1週間。
*   **結果による次の判断：** 実用的な匿名化が証明されれば、2015年からの全期間のデータ処理に移行する。精度が著しく落ちる場合は、評価期間を「知識期限以降」に限定し、観測数を増やすアプローチのみに絞る。

**3. 長期期間（10年間）でのスコア抽出とBLMポートフォリオ検証**
*   **問い：** 10年間の長期において、LLMスコアを較正済みBLMに組み込んだ戦略は、プラセボや統計モデルを有意に上回るか？
*   **方法：** 2015年以降の決算発表文をEDGARから取得し、実験2の匿名化を適用後、gpt-4o-miniでスコア化。ビューからベータを直交化し、$\Omega \propto \Sigma$、TE上限を設定したBLMバックテストを実施。対照群としてセクター内プラセボ200回を計算。
*   **成功と失敗の基準：** プラセボ・ビュー群に対する実際のビューの超過リターンの経験的 $p$ 値が0.05未満であれば成功。
*   **費用と時間の見込み：** テキストの取得は無料。スコア化のAPI費用は約20〜30ドル（予算内）。計算と分析に約2〜3週間。
*   **結果による次の判断：** この実験結果が、本プロジェクト全体の結論「LLMは追加価値を生むか」に対する最終回答となる。

**4. 回答のばらつきの「順番情報」としての活用**
*   **問い：** 確信度（回答のばらつき）は、絶対的な大きさとしては無効でも、相対的な「当たりやすさの順位」の重み付けとしては有効か？
*   **方法：** 実験3のBLMにおいて、$\Omega$の全体のスケールは較正の傾き $b_t$ で固定したまま、対角成分の銘柄間の比率のみをLLMが提示した確信度の順位に従って傾斜させる。
*   **成功と失敗の基準：** 均等な対角成分を仮定したBLMと比較して、インフォメーションレシオ（IR）が有意に向上すれば成功。
*   **費用と時間の見込み：** API追加費用なし。バックテストの調整のみで約1週間。
*   **結果による次の判断：** 成功すれば、定性評価だけでなく「LLMの出力分布」というメタ情報の新しい活用法として論文の大きなアピールポイントになる。

# 7. やらないこと

*   **新しいモデル（gpt-5.x, gemini-3.x等）を予測・スコア抽出に使用すること：**
    評価期間の相場を事前学習によって知っている（先読みしている）可能性を完全に排除できないため。研究の信憑性を担保するため、これらは考察の補助やコードレビューにのみ使用する。
*   **元の計算（SciPyのSLSQP）の再現性を追及すること：**
    H01の実験により、初期値や微小な誤差で解が大きく変わる不安定な挙動であることが証明された。研究のノイズになるため、以後はClarabelを用いた標準形式に一本化する。
*   **Gitの履歴の強制的な改変（強制プッシュによる整理）：**
    H06で91MBのテキストデータが混入した件については、履歴を消すための強制プッシュは行わない。時間的コストに見合わないため、以後のデータはSQLite等のDBへの記録に切り替える前向きな対処にとどめる。

# 8. リスクと未解決の問い

*   **リスク1：マスキングの不完全性による先読みバイアス**
    企業名や数値を伏せても、特有の事業内容や製品の描写、あるいは独自の文体からLLMが「これは2020年のテスラだ」と推測してしまい、当時の株価動向を引き出してスコアに反映させるリスクがある。
*   **リスク2：API費用の予算超過**
    2015年からの10年分の決算発表文は莫大な量になる。入力トークンの文字数制限（本文先頭15,000文字など）や構造化出力の設定を厳格に管理しないと、残り予算の約4.3万円（約300ドル強）を使い切ってしまう恐れがある。
*   **未解決の問い1：ファクターとLLMの競合**
    統計モデル（モメンタムやバリュー）とLLMのスコアが逆の方向を指し示したとき、BLMの中で両者をどう重み付けし、統合するかという最適な設計方針が未定である。
*   **未解決の問い2：下落相場での頑健性**
    これまでの評価期間（2024〜2026年）は上昇相場が主であった。2015年からの拡張によって、コロナショック等の下落局面でLLMの定性スコアが有効に働くかは全くの未知数である。

# 9. スケジュール

プロジェクトの残り期間は約5か月（2026年11月〜2027年3月）。以下の段階で進行する。

*   **第1段階（11月上旬）：短期検証とマスキングの確立**
    *   実験1（イベントスタディ）と実験2（匿名化パイプラインの構築）を実施。
    *   **判断点：** マスキング前後で十分な相関が保たれるか。保たれなければ10年間の拡張を諦め、知識期限以降のデータによるイベントスタディのみに研究スコープを縮小する。
*   **第2段階（11月中旬〜12月）：データ取得と一括スコア化**
    *   2015年以降の決算発表文の取得、マスキング、gpt-4o-miniによるスコア化を実施。
    *   **判断点：** トークン数を監視し、予算内に収まっているか。スコア抽出に致命的なエラーが起きていないか。
*   **第3段階（1月）：長期バックテストとBLM検証**
    *   実験3（10年間ポートフォリオ）、実験4（ばらつき順位の活用）を実施。
    *   **判断点：** プラセボ・ビューと比較し、最終的に「LLMは追加の価値を生んだか」の白黒をつける。
*   **第4段階（2月）：頑健性の確認と統計モデルとの比較**
    *   統計モデルの再構築、パラメータ感度分析、および今後のための「前向き記録」の仕組みをシステムに実装する。
    *   **判断点：** 評価指標（IC、TE、IR、較正の傾き）がすべて出揃い、論理的な矛盾がないか確認する。
*   **第5段階（3月）：総括とレポート執筆**
    *   実験結果の整理、LLM-BLMアーキテクチャの最終形態のドキュメント化、および大学の「情報工学工房」への最終報告書の提出。
