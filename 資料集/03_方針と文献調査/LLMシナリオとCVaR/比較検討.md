## 2. 回答のうち、そのまま受け取れない点

- **私たちの結果の読み違い**：「TE の超過は BLM の正規分布の仮定のせい」と書いているが、X02〜X04 では、主な原因は翌月のリスクの変化と最適化が推定の誤差を使うことだった。Entropy Pooling に変えれば TE が守れる、という根拠はない。
- **提案の設計（5 章）は、実験 2〜4 の結論を踏まえていない**：LLM の向きの情報は 2 日で織り込まれ、月次ではほぼ効かなかった。月次の「下落に強い銘柄の順位」を LLM に付けさせる設計は、その点に答えていない。ChronoGPT の学習なしの点数も弱かった（実験 2）。
- 「LLM は最適化には向かず、補助の入力層にとどめるのが最善」は、回答の中では複数の文献の印象をまとめたもので、検定された結論ではない。

## 3. 使える知見（照合できたものから）

1. **LLM のシナリオは、筋書きと数値を分け、数値には歯止めを置く**（Soleimani 2025）。LLM に GDP・インフレ・金利のショックを JSON で出させ、ありえない値（GDP のショック 10% 超など）を規則で落とし、線形のファクターモデルで損失に変えて VaR・CVaR を出す。検証は「数値が安定する・監査できる」までで、当たるかは検証していない。
2. **LLM の数値の予想は、楽観に偏り、自信過剰**（Chen, Green, Gulen ほか 2024）。過去のリターンを外挿し、80% の区間が狭すぎる。総合報告書 1 の「76% がプラス」と同じ向きで、LLM に下落の大きさや確率を任せない根拠になる。
3. **確率は、データの分布の上で「重み」として動かす**（Meucci 2008 の Entropy Pooling）。過去のデータから作った多数のシナリオはそのままに、見通しに合うように各シナリオの起こりやすさだけを最小限に変える。BLM より、裾の厚さや非対称を保てる。LLM のシナリオを入れる器として筋が良い。
4. **因果の筋書きに確率を付ける古典**（Rebonato 2010、ベイジアンネットワーク）。LLM でネットワークの条件つき確率を作る試み（Nafar ほか 2025）は、一般のネットワークでは偶然より良いが、金融の裾の確率の較正は確かめられていない。
5. **裾のリスクの検証は検出力が低く、新しい検定がある**（E-Backtesting、Wang & Yu 2026。元は Wang, Wang, Ziegel 2022）。CVaR を VaR なしで逐次に検定できる。少ない標本での効率の具体的な数値は未確認。

## 4. このプロジェクトへの含み

- 「LLM に筋書き、データに大きさと確率」という分担（このプロジェクトの考えと同じ）は、照合できた文献とも合う。
- 器として BLM より Entropy Pooling が向いている、という指摘は検討に値する。ただし BLM の TE の問題を解く根拠にはならない。
- 授業の研究としては、総合報告書 2 の「今後の課題」に、上の 1〜5 を根拠つきで書くのが妥当。実験として行うなら、2023-11 以降は gpt-4o-mini の先読みがないが、大きな下落がほとんどなく、CVaR の検証の検出力は低い（E-Backtesting でも同じ制約がある）。
